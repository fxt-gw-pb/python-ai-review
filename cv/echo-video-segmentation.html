心脏视频分割：代表帧、面积曲线与数据流

🧩 图像分割

心脏视频案例：把分割、时序曲线和回归分开理解

一个视频项目可能同时包含两类模型：二维分割模型逐帧预测心腔区域，视频模型利用一段连续运动预测数值。二者可以互相辅助，但输出不同、监督不同，不能把“掩码画出来了”直接当作“诊断任务完成了”。本章聚焦数据组织、分割训练和时序分析。

数据不是“视频加一个标签”这么简单

Echo 数据集类读取视频文件列表、数据划分和数值标签，再读取人工轮廓记录。一个视频包含多帧，但人工分割通常只标注特定的收缩与舒张代表帧。数据接口因此提供 LargeFrame、SmallFrame、LargeTrace、SmallTrace，分别表示较大、较小代表帧及对应轮廓 mask。

原始轮廓以线段端点记录：取一侧端点序列，再拼接另一侧反向序列，形成闭合多边形。skimage.draw.polygon 输入的是行、列，即 y、x；若顺序颠倒，会让 mask 沿对角线转置。得到的标签为 [H,W] 二值数组，图像帧为 [3,H,W]。

视频张量则是 [C,T,H,W]。标准化统计应来自训练集，并用 [C,1,1,1] 广播到整个视频。数据划分依据文件列表执行；同一来源的帧不能重新随机拆到训练和验证中，否则相似度极高的画面会造成泄漏。

分割模型怎样接收代表帧

模型采用 DeepLabV3，把最后分类卷积改为单通道。输出字典的 out 为 [B,1,H,W] logits。每个 batch 分别对大帧和小帧前向，逐像素计算 BCE，再合成损失。这是部分帧有监督的训练，不表示每个中间视频帧都有人工真值。

下面是简化教学代码，采用每像素平均损失，便于比较不同图像尺寸。

Python
import torch.nn.functional as F

def paired_frame_loss(model, large_frame, small_frame, large_mask, small_mask):
    large_logits = model(large_frame)['out'][:, 0]
    small_logits = model(small_frame)['out'][:, 0]
    loss_large = F.binary_cross_entropy_with_logits(large_logits, large_mask)
    loss_small = F.binary_cross_entropy_with_logits(small_logits, small_mask)
    return (loss_large + loss_small) / 2

先取通道零，使 logits 与 [B,H,W] 标签同形。损失内部处理 sigmoid，所以不要提前激活。例程使用像素求和，并在显示损失时除以图像像素数；换尺寸时应避免硬编码 112×112。这里改为 mean 是教学上的简化，并非逐字复制训练脚本。

分割评估分别报告大帧与小帧 Dice，再观察整体指标。较小的心腔面积对相同像素边界误差更敏感，只报告合并结果容易掩盖这一差异。

变长视频如何逐帧批处理

每个视频长度不同，不能直接堆叠成统一 [B,C,T,H,W]。逐帧分割可以先沿时间轴连接所有视频，得到 [C,总帧数,H,W]，再换轴为 [总帧数,C,H,W]。同时保留每段原始长度，推理后按累计偏移恢复视频边界。

原样核心操作如下。

Python
i = list(map(lambda t: t.shape[1], video))
video = torch.as_tensor(np.swapaxes(np.concatenate(video, 1), 0, 1))

i 保存每段帧数，concatenate(video,1) 连接时间轴，swapaxes 把帧放到 batch 位置。推理再按 block_size 分块送入模型，可以降低峰值显存，但保持原始帧序不变。它只是二维模型的批处理，不会让二维卷积自动学到时间关系。

从 mask 得到面积曲线

若每帧 logits 为 $z_t(h,w)$，则预测区域面积为

$$A_t=\sum_{h,w}\mathbf1[z_t(h,w)>0].$$

面积单位是像素。对 $-A_t$ 找峰值，相当于寻找面积谷值，可用于探索收缩时刻。平滑、最小峰距、显著性阈值都影响结果；短暂漏分、呼吸或视野移动也可能产生假谷值。应先检查原视频与掩码叠加，再解释曲线，而不能只看曲线是否“像周期波形”。

射血分数的定义使用体积：$EF=(EDV-ESV)/EDV\times100\%$。二维像素面积不能无条件代替三维体积；面积曲线主要用于观察运动与分割一致性，视频回归模型则直接以数值标签监督。把不同任务的中间量混用，会得到数值看似合理、含义却不成立的计算。

读工程时应主动发现的问题

文件路径的后缀约定要统一：列表中是否已经有 .avi，检查存在性与真正读取时是否采用同一规则，都会决定 Dataset 能否读到视频。路径应由路径工具拼接，避免 folder+'./FileList.csv' 一类字符串拼接错误。

代表帧顺序不能只依赖注释。若代码直接取轮廓记录的第一个和最后一个，需要验证数据文件是否确实按所假定的面积顺序存放。更可靠的检查是回看 mask 面积与标记，而不是根据变量名相信它。

峰值参数也有单位。将帧索引统一除以 50 相当于假设所有视频都是 50 FPS，真实时间应使用各视频元数据。百分位索引应使用 int(0.05*n) 或直接求分位数，n**0.05 是幂运算，不是第 5 百分位。此外，示例可视化循环只处理有限数量视频，少量输出图不能替代完整验证集评估。

将曲线异常定位回具体帧

面积曲线上突然出现一个很深的谷，不一定意味着真实运动发生了突变。先查看该帧是否存在模糊、视野遮挡或完全漏分，再对比前后帧的概率分布。若只是一帧预测崩溃，直接以峰值算法输出作为时刻估计就会放大分割错误；如果多帧持续变化，还需检查相机运动与目标位置是否改变。

时序后处理可以抑制短暂噪声，但平滑窗口太大会抹平真实峰谷或移动峰值时间。窗口最好用时间单位设计，再根据各视频帧率换算成帧数。评价关键帧定位时可报告时间偏差，并与区域 Dice 分开：一个模型可能轮廓整体准确，却把最小面积时刻预测晚了几帧。这种区分有助于确定下一步应该改善像素边界，还是加强时间一致性。

练习：视频边界恢复

三个视频分别有 100、80、120 帧，连接后分割结果为 [300,1,H,W]。第二个视频的结果在哪一段？

✅ 参考答案

对应切片 [100:180]，第三个从 180 开始。必须保存各段长度；不能用等分 300 的方式恢复，因为原视频长度不同。

练习：面积曲线与体积

面积由 1500 像素降到 600 像素，能否直接宣布 EF=60%？

✅ 参考答案

不能。这个比例是二维面积变化率，而 EF 定义在体积上。需要明确几何体积估计方法或使用有对应数值标签的视频回归模型，并分别验证其误差。
