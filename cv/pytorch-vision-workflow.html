PyTorch 视觉工程：张量、训练与迁移学习

🧩 图像分割

读懂视觉训练程序的五个部件

视觉工程最常见的数据流是 Dataset 读取样本，DataLoader 拼成 batch，模型产生分数，损失比较分数与标签，优化器根据梯度修改参数。先把这五个角色分清，再读 U-Net、DeepLab 或视频网络，就不容易被大量参数配置淹没。

Tensor：形状是代码里的类型说明

标量没有轴，向量有一个轴，矩阵有两个轴；图像 batch 常用 [B,C,H,W]。灰度 MNIST 的 batch 为 [64,1,28,28]，RGB 图像为 [B,3,H,W]。* 是逐元素乘法，@ 或 matmul 是矩阵乘法。二者在注意力、mask 点积和损失计算中有完全不同的含义。

reshape 改变元素的组织方式，permute 改变轴顺序。把 HWC 图像变为 CHW 需要换轴，不能只改形状。换轴后内存可能不连续，此时直接 view 可能报错；可以使用 reshape，或者明确 contiguous().view(...)。unsqueeze(0) 是增加 batch 轴，不会把图像内容复制成多个样本。

Autograd：求导与更新是两步

对于 $z=wx+b$，自动求导得到 $\partial z/\partial w=x$、$\partial z/\partial b=1$。loss.backward() 把梯度累计到参数的 .grad；optimizer.step() 才真正更新参数。每个独立 batch 应清空旧梯度，除非有意做梯度累积。retain_graph=True 保留计算图与“不清空梯度会累加”是两件事，正常的一次前向、一次反向不需要它。

nn.Module 负责登记子层与参数，nn.Parameter 表示需要纳入模型状态的可学习张量。将卷积写在 __init__ 中，是为了重复使用同一组参数；每次在 forward 里重新创建卷积会反复初始化新权重，训练行为会失去连续性。

从卷积分类器理解空间变化

一个典型的简化分类器先做 stride=1、padding=2 的 5×5 卷积，再做 stride=2 的 2×2 池化。输入 [B,1,28,28] 经第一组操作成为 [B,16,14,14]，经第二组成为 [B,32,7,7]，展平得到 [B,1568]，最后全连接得到 [B,10]。

一般卷积的输出宽度满足

$$W_{out}=\left\lfloor\frac{W+2p-d(k-1)-1}{s}+1\right\rfloor.$$

$s$ 是步长，$p$ 是 padding，$d$ 是 dilation。分割模型不能像分类器一样直接丢掉所有空间位置，因此会保留特征图、设置逐像素输出头，并恢复分辨率。池化、卷积、激活是可复用积木，是否展平由任务决定。

一个可迁移的训练与验证框架

下面为简化教学代码，假定 model 输出未经 softmax 的分类 logits，loader 返回图像和整数标签。

Python
import torch
import torch.nn.functional as F

def run_epoch(model, loader, device, optimizer=None):
    training = optimizer is not None
    model.train(training)
    total_loss, total_count = 0.0, 0
    with torch.set_grad_enabled(training):
        for images, labels in loader:
            images = images.to(device)
            labels = labels.reshape(-1).long().to(device)
            if training:
                optimizer.zero_grad(set_to_none=True)
            logits = model(images)
            loss = F.cross_entropy(logits, labels)
            if training:
                loss.backward()
                optimizer.step()
            n = images.shape[0]
            total_loss += loss.item() * n
            total_count += n
    if total_count == 0:
        raise ValueError("数据加载器为空，请检查样本列表")
    return total_loss / total_count

model.train(training) 控制 BatchNorm 与 Dropout 的行为，set_grad_enabled 控制是否记录求导图，它们不能相互替代。验证同样需要前向，但不更新模型。乘以 batch 大小后再求总平均，可正确处理最后一个不满 batch 的情况。若标签改为分割标签，不能继续 reshape(-1)，应保留空间轴并替换成对应的损失接口。

迁移学习：冻结参数不等于整段训练都配置好了

迁移学习通常先冻结特征提取器，再替换最终分类层。例如旧模型输出 1000 类，新任务只有 102 类，就用新 Linear 代替旧输出头。新层创建在冻结之后，默认仍可训练。选择 LogSoftmax + NLLLoss 或“原始 logits + CrossEntropyLoss”即可，避免把输出接口混在一起。

从只训练头部切换到全模型微调时，必须重新检查优化器的参数列表。仅把 requires_grad=True 改回来，而优化器仍持有旧的头部参数集合，其余层仍不会更新。学习率调度器也必须绑定正在使用的优化器。按 epoch 调整的 StepLR 通常推进 epoch；按验证指标调整的调度器才接收验证损失。不能把两套 step 调用含义混为一谈。

保存模型时，推理至少需要参数、类别映射和预处理配置；恢复训练还需要优化器、调度器与已完成轮数。仅保存权重并不保证“接着上次的优化轨迹继续”。预测阶段应复用训练所规定的颜色通道、缩放、归一化，而不是凭显示效果临时改一套处理。

调试时沿一条样本链逐步验证

模型一开始不收敛时，先挑一个固定样本，从文件读到最终损失逐步检查。原图是否对应正确标签，图像通道是否被意外调换，灰度图是否少了通道轴，标签是否因为 squeeze 丢掉 batch 轴，这些问题通常比网络深度更直接。把增强暂时固定为确定变换，有助于判断是模型问题还是数据在每次读取时已经变化。

随后观察一次前向的输出范围和一次反向的梯度。参数有梯度但不改变，检查优化器是否持有这些参数、学习率是否为零；梯度一直为空，检查冻结、detach 或错误的 no_grad 作用范围；损失已经是 Python 数值后再尝试 backward，则计算图已经断开。日志中的 loss.item 用于显示，可以保留原始张量继续反向，不能用显示用数值替代训练损失。

最后再扩大 batch 与样本数。损失在一个小数据子集上能明显下降，只能证明模型具有拟合能力，仍不能说明泛化良好。把该检查与独立验证集评估分开，能够在不浪费长时间训练的情况下，先排除形状、标签与更新链条的问题。每次改动只增加一个变量，也更容易将异常追踪到具体环节。

练习：找出微调不生效的原因

头部训练后把所有参数设为可求导，但优化器是 Adam(head.parameters())。为什么骨干参数不变？

✅ 参考答案

优化器只遍历创建时传入的头部参数。应在解冻后以 model.parameters() 或明确的参数组创建优化器，并让调度器绑定该优化器；随后检查骨干梯度和一次更新前后的权重差值。

练习：为什么评估要做两件事

model.eval() 已经调用，还需要关闭梯度吗？

✅ 参考答案

需要。eval 主要切换 BatchNorm 和 Dropout 等模块的运行方式，不关闭自动求导。验证使用 no_grad 或 inference_mode 可避免不必要的图与中间状态；反过来，no_grad 也不会自动切换 BatchNorm 到评估模式。
