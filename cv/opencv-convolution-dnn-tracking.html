卷积、DNN 与目标跟踪：把算法接成视频流水线

🖼️ OpenCV 图像处理

一条流水线中的三个层次

卷积描述局部数值运算；DNN 把大量带参数的层连接成网络，执行分类或检测；跟踪利用相邻帧关系延续目标位置。课程将三类示例放在一起，适合观察“像素如何进入网络，检测框如何初始化跟踪器，以及性能优化究竟优化了哪里”。

手写滑窗：先保留原始浮点结果

原 convolve 先复制边界，逐像素裁一个与核同大的 ROI，计算逐元素乘积之和，再存入输出。它没有翻转卷积核，严格说计算的是互相关；许多视觉库也用这个运算形式表达所谓卷积层。对称平滑核下翻转没有区别，非对称导数核的符号则会不同。OpenCV 的 filter2D 文档明确说明其运算为相关。OpenCV 图像滤波接口

Python
import cv2
import numpy as np

def correlate_gray(image, kernel):
    kh, kw = kernel.shape
    if kh % 2 != 1 or kw % 2 != 1:
        raise ValueError('教学实现要求奇数尺寸核')
    py, px = kh // 2, kw // 2
    padded = cv2.copyMakeBorder(image.astype(np.float32), py, py, px, px,
                               cv2.BORDER_REPLICATE)
    output = np.empty(image.shape, np.float32)
    for y in range(image.shape[0]):
        for x in range(image.shape[1]):
            output[y, x] = (padded[y:y+kh, x:x+kw] * kernel).sum()
    return output

这是原函数的教学改写，分别处理高、宽，保留负数响应。原版 padding 只根据核宽计算，隐含了正方形奇数核假设；最后缩放为 uint8 适合显示，却不宜用来核对中间数学结果。比较手写和 filter2D 时，应使用同样的边界模式和浮点输出，否则差异未必来自滑窗实现。

7×7、21×21 均值核分别取权重 $1/49$、$1/441$。大核平均范围更大，细节损失更多。锐化核中心为 5、四邻为 -1，核和为 1，保留常量区域并强化变化；Laplacian 与 Sobel 核和为 0，常量输入响应应为 0，这也是检查计算是否正确的简便例子。

DNN：图像布局变成网络布局

分类示例读取 Caffe 的网络结构与权重。结构文件定义输入 (1,3,224,224)，包含卷积、Inception 多分支、拼接、池化、1000 输出的分类层和 Softmax；标签文件也有 1000 行，类别下标必须按这个顺序解释。结构文件与权重职责不同，缺少权重不能复现训练好的分类能力。

Python
net = cv2.dnn.readNetFromCaffe('bvlc_googlenet.prototxt',
                              'bvlc_googlenet.caffemodel')
blob = cv2.dnn.blobFromImage(image_bgr, scalefactor=1.0,
                             size=(224, 224), mean=(104, 117, 123),
                             swapRB=False, crop=False)
net.setInput(blob)
predictions = net.forward()
class_id = int(np.argmax(predictions[0]))

这里显式写出各项预处理参数。输入从 HWC 转为 NCHW，单张图 blob 是 (1,3,224,224)；blobFromImages 把多张图变成 (N,3,224,224)。一般数值关系是先减均值再乘缩放系数，尺寸和颜色通道必须与模型训练约定一致。

swapRB 的官方接口默认值是 False。均值元组也应和实际通道处理一致，不能看到 RGB 三个字就机械交换通道。DNN 模块主要执行前向计算，并不是调用 forward() 就会训练网络。OpenCV DNN 接口

从分类结果到 SSD 检测框

分类输出每张图的类别分数；SSD 输出多条检测记录。跟踪示例通过 detections[0,0,i,2] 取置信度，索引 1 取类别，3:7 取归一化框坐标，再乘 [W,H,W,H] 还原像素框。示例只保留 person，其标签表有 21 项，包括背景。

模型结构声明的输入空间尺寸为 300×300，原跟踪脚本却把当前帧宽高传给 blob。部分网络实现允许调整输入，但复现该模型时应先从声明的输入和预处理建立基线，而不是假设任意尺寸都会有相同效果。结构中的检测输出层已含 0.25 的置信度门槛和 0.45 的 NMS 阈值；脚本外再用 0.2 筛选，并不能找回模型内部已经滤掉的检测。

三种目标跟踪组织方式

第一种是手选 ROI。按键选择框，再为这个框创建 KCF、CSRT 等跟踪器，每帧调用更新。边界框表示 (x,y,w,h)，绘制右下角必须加上宽高。旧代码同时引用多种创建函数，移植时应检查当前安装版本实际提供的接口，某个创建器缺失可能使字典初始化就失败。

第二种先用 SSD 检测人，给每个人创建 dlib 相关跟踪器，后续帧只更新位置。dlib 接收的框是左、上、右、下，与 OpenCV 的 x、y、宽、高不同。原慢版与快版都只在跟踪列表为空时检测，一旦建立跟踪器就不再发现新进入的人，也没有完整处理消失、遮挡和身份重关联，因此属于多框跟踪演示，不是完整的多目标身份管理系统。

第三种把每个跟踪器放到独立进程，通过输入、输出队列传帧与结果。主进程给所有跟踪器发相同 RGB 帧，再等待每个结果。它可能利用多个 CPU 核，但也引入整帧复制、进程调度与队列通信开销；目标数量少时不一定更快。

性能应如何度量

项目的 FPS 类记录开始、结束时间及处理帧数，再计算帧数除以秒数。这个数字包含哪些工作，取决于计时区间：显示等待、解码、检测、跟踪、写视频都可能在内。比较快慢版本时要用相同输入、目标数量、显示设置和输出策略。减少显示等待得到的 FPS 提升，不等于跟踪算法本身更快。

卷积输出尺寸与轻量网络

单轴卷积输出长度为 $\lfloor(n+2p-d(k-1)-1)/s\rfloor+1$，其中输入长度为 $n$，padding 为 $p$，核长为 $k$，步长为 $s$，膨胀率为 $d$。手写示例取步长 1、膨胀率 1，使用奇数核和对称 padding，因此输出高宽保持不变；把步长改成 2 后，不能只换一项循环步长而仍按原索引保存全部位置。

SSD 配套网络使用 MobileNet 思路。普通卷积同时进行空间过滤和通道混合；逐通道卷积让每个输入通道独立经过空间核，再用 1×1 卷积组合通道。结构文件中的 group 等于通道数时可以看到这种分组计算。对于输入通道数 $C_{in}$、输出通道数 $C_{out}$ 和 $k\times k$ 核，普通卷积的权重数量为 $k^2C_{in}C_{out}$，逐通道加逐点卷积约为 $k^2C_{in}+C_{in}C_{out}$，这解释了减少参数和计算的来源。

预处理的一个常见混淆是把模型推理缩放和训练数据归一化混为一谈。分类示例减 (104,117,123)，SSD 示例减 127.5 后乘约 1/127.5；两套数值约定不同，不能因为两者都调用 blobFromImage 就互换参数。排查错误时，先看 blob 的形状与数值范围，再看预测输出是否符合该模型定义。
