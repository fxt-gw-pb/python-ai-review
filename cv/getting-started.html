视觉任务、张量与实验准备

🧭 学习准备

一、计算机视觉到底在预测什么

一张图像只是像素数组。视觉算法要把数组变成有用的结构：整张图是什么、物体在哪里、每个像素属于什么。先明确输出和标签，再读网络结构，代码会容易得多。

任务 一张图的标签 模型输出示意 首先要解决的问题
图像分类 一个类别，或多个独立类别 单标签分类 logits 为 [C] 整张图的主要内容是什么
目标检测 可变数量的框与类别 N 个框、类别、分数 每个物体的位置和类型
语义分割 每个像素一个类别 [C,H,W] 的像素分类 logits 每个区域属于什么类别
实例分割 每个实例独立的掩码与类别 N 个实例掩码 两个同类物体怎样分开
全景分割 类别与实例身份 每个像素的类别及必要的实例编号 同时表达可数物体和背景区域
视频分析 帧序列及时间标签 轨迹、动作类别或逐帧结果 同一个对象随时间如何变化

C 表示类别数，H/W 表示图像高宽，N 在检测中通常是物体或预测数量。分类中的批量维常记作 B，不要把它与检测数量混淆。同一个变量名 N 在不同仓库可能含义不同，阅读时应结合形状确认。

例如停车场任务，可以先给固定车位做占用分类，也可以检测车辆再计算车辆框与车位区域的关系，还可以分割车辆像素。三种方法的标签成本、遮挡处理和结果表达都不同，不能只凭网络名称选择。

二、进入模型前，先把图像读对

1. HWC 和 CHW 的差别

OpenCV 读出的常见彩色图像是 uint8 数组，形状为 [H,W,3]，颜色顺序是 BGR。PyTorch 卷积通常接收 [B,C,H,W] 的浮点张量。

transpose/permute 改变轴的顺序；reshape 只按元素顺序重新解释形状。把 [H,W,3] 直接 reshape(3,H,W) 会打乱颜色通道和空间位置。即使最终尺寸“看起来正确”，语义也错了。

下面是完整的图像预处理示例，假定已有 data/example.jpg，并安装了 NumPy、OpenCV 和 PyTorch。

Python
from pathlib import Path
import cv2
import numpy as np
import torch

path = Path("data/example.jpg")
bgr = cv2.imread(str(path), cv2.IMREAD_COLOR)
if bgr is None:
    raise FileNotFoundError(f"无法读取图像：{path}")

rgb = cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB)  # [H, W, 3]
image = rgb.astype(np.float32) / 255.0    # 整数转浮点，范围约 [0, 1]
chw = np.ascontiguousarray(image.transpose(2, 0, 1))
x = torch.from_numpy(chw).unsqueeze(0)   # [1, 3, H, W]
assert x.ndim == 4 and x.shape[1] == 3
print(x.shape, x.dtype, x.min().item(), x.max().item())

第一步检查 imread 的返回值，避免把路径错误误判为颜色转换失败。第二步显式转换 BGR → RGB。第三步先转浮点再除以 255；这一操作与减均值、除标准差的标准化不同。第四步交换维度，再创建连续数组，便于与后续张量操作衔接。最后 unsqueeze(0) 添加批量维，一张图也按一个 batch 送进模型。

是否需要 RGB、是否除以 255、是否减均值，应与模型训练时的设置一致。若预处理库已经完成缩放，再除以 255 会让输入过小。

2. 图像与标签必须共享几何变换

随机裁剪、翻转、缩放会改变目标位置，图像和框或掩码必须使用同一次随机参数。只变换图像会让监督信息失配。

对类别编号掩码，缩放应使用最近邻插值。例如背景为 0、目标为 2，双线性插值可能产生数值 1，但这个数字并不代表合理的新类别。RGB 图像通常可使用双线性等连续插值。类别 ID 掩码和表示概率的软掩码要分清。

三、坐标约定决定检测框是否正确

常见框表示是 xyxy = [x1,y1,x2,y2] 和 cxcywh = [cx,cy,w,h]。这里采用连续坐标，不对宽高加 1：

$$ w=x_2-x_1,\qquad h=y_2-y_1,\qquad c_x=(x_1+x_2)/2,\qquad c_y=(y_1+y_2)/2. $$

转换成 YOLO 常用的归一化表示时，横向分量除以图像宽 W，纵向分量除以高 H。一个图像的宽高若写反，方形图可能掩盖错误，长方形图就会明显错位。

这个示例可直接运行，不依赖图像或深度学习框架。

Python
def xyxy_to_yolo(box, image_width, image_height):
    x1, y1, x2, y2 = map(float, box)
    if image_width <= 0 or image_height <= 0:
        raise ValueError("图像宽高必须大于零")
    if not (0 <= x1 < x2 <= image_width and 0 <= y1 < y2 <= image_height):
        raise ValueError("框必须位于图像内，且宽高为正")
    return (
        (x1 + x2) / (2 * image_width),
        (y1 + y2) / (2 * image_height),
        (x2 - x1) / image_width,
        (y2 - y1) / image_height,
    )

result = xyxy_to_yolo([100, 50, 300, 150], 400, 200)
assert result == (0.5, 0.5, 0.5, 0.5)
print(result)

函数的输入是像素坐标，输出是四个无量纲比例。标签中的类别编号需要另加在最前面，不能参与除以宽高。转换函数选择遇到越界就报错，便于在训练前发现标注问题；实际数据清理也可以裁剪越界框，但应记录被修改的标签。

经过 letterbox 的图片同时发生缩放和平移，预测框映射回原图时需要先减去 padding，再除以缩放比例。简单乘原图宽高只适合相应的归一化坐标，不能适用于所有后处理结果。

四、按数据流读代码，比按文件顺序有效

先追踪一条样本，依次确认六个位置。

  1. Dataset：一条样本返回什么，图像和标签的类型、形状是什么。
  2. DataLoader / collate：如何把样本组成 batch。检测框数量不一致时通常不能直接堆成普通矩阵。
  3. forward：主干提取哪些特征，融合层怎样改变尺度，任务头输出哪些张量。
  4. loss：预测与标签如何对齐，哪些位置参与监督，正负样本如何分配。
  5. optimizer：何时清空梯度、反向传播和更新权重，有没有梯度累积。
  6. postprocess / evaluator：怎样把原始输出变成框、类别或掩码，指标在哪个坐标系中计算。

以单标签语义分割为例，模型可能输出 [B,C,H,W] 的 logits，目标是 [B,H,W] 的整数类别 ID。交叉熵接收 logits，预测图通常通过 argmax(dim=1) 得到。训练时先 argmax 会切断需要优化的连续概率关系；先做 softmax 再交给交叉熵也与通常接口预期不一致。

二值分割常用 [B,1,H,W]。若使用 BCEWithLogitsLoss，输入应是 logits；若模型已经输出 sigmoid 概率，应检查是否配 BCELoss。不能因为两种结果尺寸相同就互换。

五、一次可靠实验的最低要求

先在少量样本上验证图像、标签、模型输出和损失。确认模型能把一个极小训练集拟合下来，再扩大训练。若小样本都无法拟合，首先排查标签、损失输入、梯度和学习率，而不是立即增加网络深度。

训练和验证需要独立。相邻视频帧或同一患者的多张图像很相似，随机按图片拆分可能把同一主体分到两边，导致验证分数虚高。应按患者、视频、拍摄批次等任务相关单位划分。

model.eval() 切换 Dropout、BatchNorm 等模块的行为，torch.no_grad() 关闭梯度记录；二者作用不同。验证一般需要同时使用它们。单纯关闭梯度并不会自动进入评估模式。

为每次实验记录数据划分、类别映射、输入尺寸、归一化方式、模型配置、优化器与指标。不要只保存一个权重文件，否则后续难以还原它期待的输入。

学习过程中可把实验分成三档：不依赖数据的坐标和张量小例子、使用少量样本的前向与损失检查、依赖完整数据和算力的训练。网页中的教学片段用于解释局部逻辑，仓库级训练还需要对应依赖、数据与预训练权重，不能把片段当作完整工程入口。

六、自测与参考答案

1. 为什么 [480,640,3] 不能直接 reshape 成 [3,480,640]？

✅ 参考答案

因为 reshape 没有把每个像素的三个交错通道重新分组，只改变了同一串元素的维度解释。正确方式是交换轴：NumPy 使用 transpose(2,0,1)，PyTorch 使用 permute(2,0,1)。

2. 检测框宽高归一化时，图像是 800×400，框宽 200、高 100，结果是多少？

✅ 参考答案

若 800 是图像宽、400 是图像高，则归一化宽为 200/800=0.25，高为 100/400=0.25。OpenCV 的 image.shape[:2] 返回顺序是 (H,W)，这里应得到 (400,800)。

3. 验证阶段已经 no_grad，为什么同一张图的输出仍可能随 batch 改变？

✅ 参考答案

如果没有执行 model.eval()，BatchNorm 可能继续使用当前 batch 的统计量，Dropout 也可能继续随机丢弃单元。关闭梯度只影响自动微分记录，不负责切换这些模块的运行行为。
