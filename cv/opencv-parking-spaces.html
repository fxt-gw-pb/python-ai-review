停车场车位识别：固定几何地图与图像分类结合

🖼️ OpenCV 图像处理

先定位车位，再判断是否占用

这个项目把任务拆成两部分：利用固定视角下的车位线建立车位坐标表，再裁出每个车位的小图做空闲与占用二分类。因此分类网络只回答给定区域内是否有车，不负责自动发现整个场景中所有车位。读懂这个分工，才知道更换摄像头后应该重新标定几何区域，而不是只重新加载模型。

颜色与边缘筛选的真实含义

输入测试图由 Matplotlib 读取，后续灰度转换使用 RGB 顺序。名为 select_rgb_white_yellow 的函数实际只保留三个通道都在 120–255 的像素，即亮色近白区域，并没有单独实现黄色筛选。函数名表达的目标与代码真正做的事情要区分。

接着转灰度、Canny 检测边缘、用手工多边形限制感兴趣区域。多边形顶点按图像宽高比例设置，可以随分辨率缩放，但仍绑定停车场布局和摄像头位置。它不会自动识别“哪里是停车场”。

Python
import cv2
import numpy as np

bright_mask = cv2.inRange(rgb_image, np.uint8([120, 120, 120]),
                          np.uint8([255, 255, 255]))
selected = cv2.bitwise_and(rgb_image, rgb_image, mask=bright_mask)
gray = cv2.cvtColor(selected, cv2.COLOR_RGB2GRAY)
edges = cv2.Canny(gray, 50, 200)
lines = cv2.HoughLinesP(edges, rho=0.1, theta=np.pi/10,
                       threshold=15, minLineLength=9, maxLineGap=4)

这是原方法的简化片段，输入应与原码一样使用 0–255 的 RGB 图。若图像加载接口返回 0–1 浮点值，阈值 120 会使掩模全黑；如果视频帧来自 OpenCV，则最初是 BGR，需统一颜色约定。

霍夫线段如何变成车道

霍夫方法在参数空间中寻找支持直线的边缘点。rho 是距离分辨率，theta 是角度分辨率，threshold 是投票门槛，最短长度与最大间隙控制最终线段。原参数中的 np.pi/10 是 18 度，不是精细到 0.1 度的搜索。

检测后只保留高度差不超过 1、横向长度在 25–55 像素之间的近水平线。再按起点 x、y 排序，把相邻 x 起点距离不超过 10 的线段归为一组。每组至少需要较多线段，去重后以最上、最下 y 和平均左右 x 定出车道矩形。这里的“聚类”是手写的相邻距离分组，并非调用通用聚类模型。

原代码直接遍历 lines，如果没有检测到线段，它可能是 None，应先检查。线段端点顺序、重复边缘以及遮挡都会影响聚类；不应仅因为输出了十二个矩形，就认定车位地图正确。

车位切分中的人工标定

每列车道按 15.5 像素的间隔切分，内部车道再从中间一分为二，左右两侧车道只保留单列。代码还有针对各列的 x、y 调整字典，明确体现了人工微调。换视角后照抄字典没有可迁移的几何含义。

坐标表将 (x1,y1,x2,y2) 映射到车位编号，再用切片提取每块。因为间隔为浮点数，真正切片前必须转整数。还要检查最后一格是否超出车道边界，避免 num_splits+1 带来的额外小格或越界裁剪。对固定摄像头，人工审核并保存可信车位区域往往是合理的工程步骤。

分类网络到底训练什么

训练脚本加载去掉顶层的 VGG16，输入为 48×48×3；冻结前十层，再接 Flatten 和两类 Softmax，用交叉熵训练。前十层被冻结，不意味着整个特征提取网络都冻结。其余可训练层与新分类头共同调整，使图像特征适应车位任务。

训练生成器把像素除以 255，并加入翻转、缩放、平移和小角度旋转。验证生成器也加入了随机增强，会让每轮验证受随机变化影响；较清楚的基线通常让验证预处理保持确定，只在明确要评估扰动鲁棒性时做额外增强实验。示例采用 ImageNet 权重却用简单缩放，应理解这是原项目配置，不要宣称它等同于所有 VGG16 预训练模型的标准预处理。

同一视频里相邻帧高度相似。若训练和验证混入同一时刻、同一车辆的近重复裁剪，验证分数会高估泛化。更有意义的是按拍摄时间、光照或完整场景划分，单独观察阴影、遮挡、夜间和空车位线磨损等情况。

推理张量与训练约定

Python
crop = frame_rgb[y1:y2, x1:x2]
if crop.size == 0:
    raise ValueError('车位裁剪为空')
crop = cv2.resize(crop, (48, 48))
batch = np.expand_dims(crop.astype(np.float32) / 255.0, axis=0)
probabilities = model.predict(batch)
class_id = int(np.argmax(probabilities[0]))
label = index_to_label[class_id]

这是原预测函数的教学整理。单张图从 (48,48,3) 加批次维变为 (1,48,48,3)；模型返回每类的分数。训练和推理要统一颜色、缩放、尺寸与标签次序，标签表应从训练目录的类别映射保存，不能假设 0 永远等于空闲。

原视频每五帧做一次预测，节省计算但会降低更新频率；它逐车位单独调用模型，扩展时可把全部车位叠成一个 batch。处理读取结果必须先判断帧是否有效，再进行复制和裁剪。显示空闲数时可以用一段时间内的稳定状态抑制瞬时闪烁，但应说明由此引入的响应延迟。

练习

  1. 为什么这个系统更换相机位置后，分类模型没变也可能全部失效？
  2. 20 个车位一起预测时，输入 batch 的形状是什么？
  3. 训练读取 RGB、视频推理直接用 BGR，会发生什么？
✅ 参考答案
  1. 车位区域和几何阈值已不对应新画面，裁剪得到的内容就错了。先重新标定车位，再评估分类器是否需要适配。
  2. (20,48,48,3)，前提是模型使用该项目的通道末尾布局。
  3. 通道语义不一致，预训练特征和训练得到的颜色关系被改变。即使没有运行错误，预测也可能退化，应在入口显式统一。
