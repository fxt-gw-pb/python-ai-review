U²-Net：残差 U 形块与显著目标分割

🧩 图像分割

U²-Net：在 U 形网络内部再放 U 形块

U²-Net 常用于显著目标分割：从图像中预测主要前景区域。它和 U-Net++ 的嵌套方向不同。U-Net++ 强化不同阶段之间的密集跳跃路径，U²-Net 则把普通卷积块换成内部也有编码、解码结构的 Residual U-block，简称 RSU。外部是一条大 U，内部每个块又是一条小 U。

RSU 为什么需要局部编码解码

一个普通 3×3 卷积只直接访问邻域。RSU 先把输入映射到输出通道，再在块内逐级池化、卷积、上采样，把多个尺度的上下文带回原分辨率。最后将局部变换结果与最开始的映射相加：

$$Y=H_{in}(X)+U_{block}(H_{in}(X)).$$

这里的残差是相对 hxin 而非原始 x，因为输入输出通道可能不同。例如 RSU7(3,32,64) 把 RGB 映射到 64 通道，内部主要使用 32 通道，最后再恢复为 64，与 hxin 相加。

RSU7 里的 7 体现块内结构深度。其池化使用 ceil_mode=True，遇到奇数尺寸会向上取整。因此恢复尺寸时调用 _upsample_like(src, tar)，把来源特征显式插值为目标特征的高宽；不能只乘二后假设一定对齐。

下面是简化教学代码，保留残差与局部跳跃的关键关系。

Python
hxin = input_projection(x)           # [B,out_ch,H,W]
h1 = conv1(hxin)                     # [B,mid_ch,H,W]
h2 = conv2(pool(h1))                 # [B,mid_ch,ceil(H/2),ceil(W/2)]
deep = dilated_conv(h2)
up = torch.nn.functional.interpolate(
    deep, size=h1.shape[-2:], mode='bilinear', align_corners=False)
local = decode(torch.cat([up, h1], dim=1))
output = local + hxin

cat 保留编码端与解码端两组信息；decode 将通道整理回 out_ch；最后的加法提供残差路径。这是缩短的 RSU 教学块，完整 RSU7 还包含更多中间尺度。不可用这几行代码的层数去判断完整模型参数量。

深层为何使用 RSU4F

外层编码器越往下，特征图已经越小，继续多次池化可能过度压缩。RSU4F 通过不同 dilation 的卷积扩大感受野，保持空间分辨率，而不再在块内继续池化。这个设计说明“上下文范围”并不只能靠降低分辨率获得。

完整模型的六个编码阶段与对应解码阶段构成外层 U。轻量 U2NETP 使用更窄的中间通道，但仍保留同类结构。小模型不等于随机删除几个模块；需要维持每个拼接点、残差端的形状兼容，并使用与该结构匹配的权重。

六个侧输出与一个融合输出

六个不同尺度的侧输出先恢复到第一层分辨率，再沿通道拼接，1×1 卷积生成融合输出 d0。在二值设置下，各侧输出为 [B,1,H,W]，拼接为 [B,6,H,W]，融合后又是 [B,1,H,W]。

网络返回的七个张量已经经过 sigmoid。训练程序据此使用 BCELoss，不是 BCEWithLogitsLoss。下面是损失函数的原样核心节选。

Python
loss0 = bce_loss(d0, labels_v)
loss1 = bce_loss(d1, labels_v)
loss2 = bce_loss(d2, labels_v)
loss3 = bce_loss(d3, labels_v)
loss4 = bce_loss(d4, labels_v)
loss5 = bce_loss(d5, labels_v)
loss6 = bce_loss(d6, labels_v)
loss = loss0 + loss1 + loss2 + loss3 + loss4 + loss5 + loss6

loss0 便于观察融合输出，loss 才是参与反向传播的全部监督。若改为数值更稳定的 logits 方案，应同时移除模型末尾 sigmoid 并改成 BCEWithLogitsLoss，不能只改损失名字。七项求和与七项平均也改变梯度规模，比较训练时必须保持一致。

数据流与训练设计

训练例程将显著目标图像缩放至 320，再随机裁剪至 288，随后进行张量转换与标准化。标签使用最近邻缩放、保留范围，并转成单通道监督。裁剪必须对图像和标签同步；如果裁剪常把目标完全移出画面，需要检查空前景样本比例。

例程以固定迭代间隔存盘，但没有完整的验证集选择最佳模型过程。完善实验时，应先分好训练和验证来源，固定验证预处理，每轮统计前景 IoU、Dice 与边界错误，再按验证指标选模型。超大的 epoch_num 只是脚本循环上限，不是合理训练轮数的保证。

推理阶段取第一个返回值，即融合预测。有的变量被重新命名为 d1，阅读时要追踪返回顺序，不能只凭变量名误认为取了第一侧输出。

预测图归一化的陷阱

normPRED 采用 (d-min)/(max-min) 拉伸单张图。这适合调整展示对比度，却会改变不同图片之间的概率含义：即使整张图原始概率都很低，拉伸后也可能出现接近 1 的区域。做定量评估时，应直接用模型原始概率和固定阈值。若全图为常数，还需防止分母为零。

另一个容易忽略的限制是融合卷积固定接收六通道，因此当前实现针对 out_ch=1 的二值输出。简单把类别数改为多个，六个侧输出拼接将变成 6*C 通道，融合层和损失定义必须一起改。

对比侧输出时看什么

浅层侧输出靠近原图分辨率，容易保留边缘纹理，也可能把背景纹理当成前景；深层侧输出拥有更大上下文，区域判断可能更完整，却容易失去细枝与孔洞。融合输出通过卷积学习不同侧输出之间的关系，而不是固定求平均。因此不要把融合权重看成六个全局标量，它是在每个位置的通道组合上学习映射。

可以选择一张包含细发丝、一张目标很小、一张前景接近背景颜色的样本，分别观察七张概率图。记录错误属于漏掉细节、区域破碎、孔洞填满还是背景误检，再检查对应标签本来是否有这些细节。若标签已经过度缩小，单纯增加网络容量无法恢复监督中没有的边界。

为了评价轻量版本，应使用相同图像预处理和硬件，在相同 batch 下比较完整推理过程。仅比较权重文件大小无法推断实际速度，因为算子、特征图尺寸和内存访问也影响延迟。训练阶段七路监督所需的中间状态，比推理只使用最终结果更占内存；配置训练 batch 时不能直接照搬推理可容纳的数量。

练习：为什么损失配对出错

把 U²-Net 输出直接传给 BCEWithLogitsLoss 会发生什么？

✅ 参考答案

输出已经是 0 到 1 的概率，而该损失会把输入当作 logit 再执行内部 sigmoid，导致概率再次被压缩，监督含义错误。应保留 BCELoss，或者移除模型 sigmoid 后再整体切换。

练习：评估中的 min-max

模型给一张空前景图所有像素预测 0.01 到 0.02，先 min-max 再阈值 0.5 有什么问题？

✅ 参考答案

拉伸把很弱的概率差异变成 0 到 1，大量像素会被误判为前景。固定阈值应应用在原始概率上；展示用拉伸结果应单独处理，不参与指标计算。
