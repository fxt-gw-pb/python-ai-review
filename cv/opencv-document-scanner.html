文档扫描与 OCR：从四个角点恢复平整页面

🖼️ OpenCV 图像处理

扫描与文字识别是两个阶段

手机斜拍的纸张会出现透视变形。扫描阶段把四边形纸面拉成矩形、改善文字对比度；OCR 阶段才把图像变成字符串。原项目也分成两个脚本：一个保存扫描图，另一个读取扫描图并调用文字识别。前处理能让输入更合适，但不能保证文字引擎一定认出所有语言和字体。

在小图检测，在原图变换

原流程把图像缩到高 500，先转灰度，用 5×5 高斯模糊抑制噪声，再用 Canny 找边缘。这样检测更快，而最终透视变换仍在原图执行，以保留字符细节。

设原图高度为 $H$，检测图高度为 500，则比例 $r=H/500$。在小图检测出的角点 $(x_s,y_s)$ 需要映射回 $(rx_s,ry_s)$。这个比例成立的前提是等比例缩放。若宽高被独立缩放，应分别使用两个比例。

候选轮廓按面积从大到小排序，只检查前五个，对每个轮廓用 $\epsilon=0.02\times\text{周长}$ 做多边形近似，遇到四个顶点就作为纸张。这个方法利用“纸张常是显著的大四边形”的假设。相框、桌面和屏幕也可能满足，应结合面积占比、位置、凸性和长宽比进一步筛选。

Python
import cv2

edges = cv2.Canny(cv2.GaussianBlur(gray_small, (5, 5), 0), 75, 200)
contours = cv2.findContours(edges.copy(), cv2.RETR_LIST,
                            cv2.CHAIN_APPROX_SIMPLE)[-2]
paper = None
for contour in sorted(contours, key=cv2.contourArea, reverse=True)[:5]:
    perimeter = cv2.arcLength(contour, True)
    approx = cv2.approxPolyDP(contour, 0.02 * perimeter, True)
    if len(approx) == 4 and cv2.isContourConvex(approx):
        paper = approx.reshape(4, 2)
        break
if paper is None:
    raise ValueError('未找到可信的纸张四边形')

这段是教学改写，增加空结果与凸性检查。原程序未找到四点时可能继续使用未定义变量；这种失败应该被显式表达，而不是等到后面的矩阵运算才报错。轮廓近似容差过大可能把复杂物体“削”成四边形，所以四个点本身不是充分证据。

四个点必须按对应关系排列

透视变换需要把左上、右上、右下、左下分别映射到目标矩形对应角点。原 order_points 用 $x+y$ 最小、最大找左上与右下，再用 $y-x$ 最小、最大找右上与左下。这里 np.diff(pts, axis=1) 对每行两个坐标求差，确实是 y 减 x。

这种方法容易理解，但当四边形接近菱形或坐标和、差出现并列时，可能选中同一点。可检查四点是否互异、边是否交叉和面积是否足够；更通用的排序可以结合中心角顺序和顶点方向判断。不要把一个依赖典型拍摄姿态的点排序技巧当作任意四边形都无歧义的数学定理。

单应矩阵如何恢复页面

输出宽度取上下边长度的较大值，高度取左右边长度的较大值，以容纳纸面。目标坐标分别为 (0,0)、(W-1,0)、(W-1,H-1)、(0,H-1)。矩阵 $M$ 在齐次坐标下满足 $s\mathbf{p}'=M\mathbf{p}$，并通过最后一个分量做归一化；它能够表达透视压缩，不只是平移和缩放。

Python
import numpy as np

rect = ordered_points.astype(np.float32)
tl, tr, br, bl = rect
width = int(max(np.linalg.norm(br-bl), np.linalg.norm(tr-tl)))
height = int(max(np.linalg.norm(tr-br), np.linalg.norm(tl-bl)))
if width < 2 or height < 2:
    raise ValueError('角点构成退化页面')
destination = np.float32([[0, 0], [width-1, 0],
                          [width-1, height-1], [0, height-1]])
matrix = cv2.getPerspectiveTransform(rect, destination)
scanned = cv2.warpPerspective(original, matrix, (width, height))

这是 four_point_transform 的教学简化；ordered_points 必须已经恢复到 original 的坐标系。getPerspectiveTransform 估计矩阵，warpPerspective 再采样像素，两者不是同一件事。结果像素并非每个都恰好落在原图整数格点上，因此插值会影响细字符。

二值化与 OCR 输入

原扫描脚本使用固定阈值 100 保存 scan.jpg。固定阈值便于观察，但纸张阴影会使同一字在不同位置亮度不同。可以比较固定阈值、Otsu 和局部阈值的效果，判断字符是否断笔、粘连，是否连细小标点一起滤掉。不要为了背景全白而牺牲文字。

原 OCR 脚本可选择 Otsu 或 3×3 中值滤波，临时写出 PNG，再让 pytesseract.image_to_string 读取。pytesseract 是调用接口，运行还需要本机已有 Tesseract 程序与相应语言模型。应先在运行环境中确认引擎和所需语言可用。

对于已有的 PIL 图像对象，教学代码可以直接传入，避免为了接口转换而保留临时文件：

Python
from PIL import Image
import pytesseract

text = pytesseract.image_to_string(Image.fromarray(scan_gray))
print(text)

这个例子假设引擎可用且 scan_gray 是灰度 uint8 数组。选择语言和页面分割方式需要根据实际文档确定；运行失败要分别检查程序路径、语言数据、输入图像和识别参数，而不是全部归结为扫描算法问题。

练习

  1. 原图高 2000，检测图高 500；检测点 (80,120) 应映射到哪里？
  2. 如果图像拉正后上下颠倒，优先检查哪个环节？
  3. 为什么固定阈值对白纸阴影可能不稳？
✅ 参考答案
  1. 比例为 4，原图坐标为 (320,480)。
  2. 角点排序与源点、目标点的对应关系，之后再检查坐标缩放和图像方向。
  3. 相同背景在亮处和阴影处的灰度不同，一个阈值可能同时把阴影当文字、把浅色文字当背景；应先观察光照分布再选择阈值方法。
