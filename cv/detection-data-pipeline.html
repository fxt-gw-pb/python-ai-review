目标检测标注与数据管线

🎯 目标检测

标签是一种坐标协议

检测训练最常见的隐蔽错误来自标签。图片能读、损失能计算，并不说明坐标正确。标注工具、数据转换脚本、增强代码、损失函数和可视化工具必须使用一致的坐标协议。

YOLO 文本每行通常包含 class_id cx cy width height。类别编号从 0 开始，四个坐标相对图片宽高归一化。COCO 的 bbox 则通常表示未归一化的左上角与宽高 [x, y, w, h]，并通过 image_id、category_id 关联图片与类别。VOC XML 使用 xmin/ymin/xmax/ymax，需要确认数据集的端点约定。

以宽 640、高 480 的图片和边界框 $(160,120,480,360)$ 为例，YOLO 标签是中心 $(0.5,0.5)$、宽高 $(0.5,0.5)$。四个数中的 x 和宽度除以 640，y 和高度除以 480；全部除以同一个边长只适用于已统一成正方形的坐标系。

把矩形转换成 YOLO 标签

下面是针对零起点连续坐标的教学修正版。它保留转换逻辑，同时处理矩形两个点的点击顺序、越界和零面积情况：

Python
def rectangle_to_yolo(points, image_width, image_height):
    if image_width <= 0 or image_height <= 0:
        raise ValueError('图片尺寸必须为正')
    xs, ys = zip(*points)
    x1 = max(0.0, min(float(min(xs)), image_width))
    x2 = max(0.0, min(float(max(xs)), image_width))
    y1 = max(0.0, min(float(min(ys)), image_height))
    y2 = max(0.0, min(float(max(ys)), image_height))
    if x2 <= x1 or y2 <= y1:
        raise ValueError('边界框没有有效面积')
    return ((x1 + x2) / (2 * image_width),
            (y1 + y2) / (2 * image_height),
            (x2 - x1) / image_width,
            (y2 - y1) / image_height)

min/max 让先点右下角再点左上角也能工作；裁剪把坐标限制在图片内部；最后四行完成归一化。不要在标签转换时提前取整，亚像素精度本来可以保留。

课程中的两份 JSON 转换脚本内容相同，都在中心坐标上减去 1。减 1 是否正确取决于标注坐标是否从 1 开始，不能把它当作 YOLO 的规则。对于零起点坐标，不应随意减 1。还需要将固定机器上的目录改为参数，按 .json 后缀筛选输入，明确文本编码，并为未知类别报错。类别名称中包含空格没有问题，真正写入标签的是它对应的整数编号。

图片变换与标签必须同步

检测的数据增强同时作用于图片和几何对象。水平翻转时，归一化中心满足 $c_x'=1-c_x$，宽高不变。像素坐标下则是 $x_1'=W-x_2$、$x_2'=W-x_1$。这里应先保存旧坐标，不能更新 x1 后再用已经变化的 x1 计算 x2。

Letterbox 先按比例缩放，再填充边界。设原图为 $W\times H$，目标画布为 $S_w\times S_h$，则缩放比例 $r=\min(S_w/W,S_h/H)$。若左、上填充分别为 $p_x,p_y$，新坐标满足 $x'=rx+p_x$、$y'=ry+p_y$。推理后要执行逆变换 $x=(x'-p_x)/r$。

例如 640×480 图缩放到 416×416，$r=0.65$，有效图像为 416×312，上下各补 52 像素。框 $(160,120,480,360)$ 变为 $(104,130,312,286)$。把新图像上的框直接画回原图，会出现整体偏移与尺度错误。

课程中的不同管线填充方式不同：YOLOv3 先补成方形再缩放，YOLOv5 的 letterbox 返回缩放比例与 padding，EfficientDet 把缩放后的图放在画布左上角。它们的坐标还原公式必须跟随各自的预处理方式。

变长标注如何组成 batch

图片可以组成 [B,3,H,W]，但每张图的物体数不同。常见做法有三种：拼接所有框并附加图片编号；用列表逐张保存；填充到 batch 内最大物体数并用掩码标记无效行。YOLO 常用第一种，DETR 常用第二种，课内 EfficientDet 使用第三种。

下面是拼接标注的教学实现，单张标签张量形状为 [N_i,5]：

Python
import torch

def collate_detection(batch):
    images, labels = zip(*batch)
    merged = []
    for image_index, boxes in enumerate(labels):
        if boxes is None or boxes.numel() == 0:
            continue
        image_ids = boxes.new_full((len(boxes), 1), image_index)
        merged.append(torch.cat([image_ids, boxes], dim=1))
    targets = (torch.cat(merged, dim=0) if merged
               else images[0].new_zeros((0, 6)))
    return torch.stack(images), targets

关键是先按原 batch 顺序编号，再跳过空标注。若先删除空标签，再重新从 0 编号，第二张图片的框可能被错误分配给第一张图片。全为空的 batch 也应得到形状正确的空张量，而不是让 torch.cat([]) 报错。

准备一份可复现的数据集

先固定类别顺序，再统一转换标签，最后按采集对象或场景划分训练、验证与测试集。如果同一视频的相邻帧随机进入不同集合，模型可能只是识别了几乎相同的背景。钢材缺陷、口罩和海洋生物是资料中的不同任务，不能把各自的类别编号表混用。

一份合格的检查报告应包括图片数、框数、每类实例数、空标注数、损坏图片数和越界框数。随机抽取样本把转换后的标签画回原图，检查细长框、边缘目标、同图多目标和空图。然后做少量图片的过拟合试验：关闭强增强，让模型反复学习十几张图；若仍无法把这些图学好，优先检查标签与损失链路。

空图片可能是有效负样本，也可能是漏标。两者对训练的含义相反。有效负样本帮助模型学习背景；漏标则会把真实物体当作负例惩罚。是否过滤空标签，需要根据任务与标注完整度决定。

类别映射必须贯穿训练和评估

假设 COCO 标注使用类别 ID 3、7、12，模型只输出三个目标类别。训练前应建立 {3:0,7:1,12:2} 映射；推理得到类别索引1时，写回COCO结果需要恢复为ID7。简单减1会得到2、6、11，既可能超出分类头维度，也可能悄悄落到错误类别。

类别名称文件、训练配置和标注转换脚本都应使用同一张映射表。某些任务名称大小写或空格不同，转换时要明确是统一命名还是拒绝未知类别，不能默默跳过。静默跳过会让模型把被遗漏的真实物体当作背景，后续再调整网络结构也无法修复这类监督错误。

图片路径同样需要往返检查：文件名相同不意味着内容相同，训练与验证目录中可能有复制图片。对文件内容做哈希去重，可以检查完全相同图片的交叉泄漏；对于相邻视频帧等近似重复，还应按采集来源分组划分。

练习：排查整体偏移

补边后所有框都向下偏移，宽高却基本正确，最可能漏掉了哪个量？某 batch 第一张为空图、第二张有框，拼接标签中第二张图片编号应是多少？

✅ 参考答案

整体竖直偏移首先检查上边 padding 的加减方向，以及推理坐标还原时是否减去了 padding。第二张图片编号必须为 1；即使第一张没有框，它仍占据 images 张量中的第 0 个位置。删除空标注不能改变图片在 batch 中的位置。
