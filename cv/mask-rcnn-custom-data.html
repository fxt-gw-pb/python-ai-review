Mask R-CNN 自定义任务：实例标注与分阶段训练

🧩 图像分割

自定义实例分割：标签映射比启动训练更关键

将 Mask R-CNN 迁移到自己的类别，最容易出问题的是实例 mask 与类别数组没有一一对应。训练框架需要知道一张图里有几个独立对象、每个对象的区域是什么、它属于哪个类别。图像能够显示、loss 能够计算，都不足以证明标签接口正确。

从 LabelMe 到实例张量

常见处理流程是读取多边形标注，生成实例编号图，再拆成多个二值通道。例如整数图中 0 表示背景、1 表示第一个物体、2 表示第二个物体。拆分后得到 [H,W,N]，每个通道对应一个物体；另有 [N] 的类别编号数组。

要区分“实例编号”和“类别编号”。两个不同的人应有不同实例编号，但类别编号相同。不能把类别值为 1 的所有像素直接当成唯一实例，否则相邻同类物体会合并。若编号图的最大值为 9，也不一定有 9 个物体：实例编号可能不连续。

示例 DrugDataset 继承框架 Dataset：add_class 注册类别，add_image 登记路径及尺寸，prepare 建立内部索引，load_mask 才真正返回实例 mask 与类别。类别映射通常保留零给背景，所以两个前景类别的 NUM_CLASSES 应为 3。

用向量化方式构造 mask

原始示例通过三层循环逐像素拆 mask，既慢，也假设实例编号从 1 连续增长。下面是更清楚的简化教学代码；class_by_instance 必须来自标注映射，不能从实例编号大小猜类别。

Python
import numpy as np

def split_instances(instance_map, class_by_instance):
    instance_ids = np.unique(instance_map)
    instance_ids = instance_ids[instance_ids != 0]
    h, w = instance_map.shape
    if len(instance_ids) == 0:
        return np.zeros((h, w, 0), dtype=bool), np.zeros((0,), dtype=np.int32)
    masks = np.stack([instance_map == i for i in instance_ids], axis=-1)
    class_ids = np.array([class_by_instance[int(i)] for i in instance_ids],
                         dtype=np.int32)
    assert masks.shape[-1] == class_ids.shape[0]
    assert np.all(class_ids > 0)
    return masks, class_ids

np.unique 找到实际出现的编号；比较运算生成布尔区域；stack(axis=-1) 将实例放到最后一轴。类别数组严格使用同一顺序构造，因此第 $k$ 个 mask 与第 $k$ 个类别天然对应。空图也返回合法形状，避免 mask[:,:,-1] 在零实例时越界。

框可由各实例非零像素的最小最大坐标推导，但必须处理空 mask 与坐标右边界约定。缩放、padding、裁剪应同时作用到图像和所有 mask，框再按框架约定更新或重新计算。遮挡关系也应来自实例标注，而不是用一个固定 count=1 的循环假装处理了全部对象。

训练集与验证集必须真正独立

演示代码中容易出现“先把所有图片作为训练集，再取前七张作为验证集”的写法。这只能用于检查流程能否跑通，不能用于判断泛化。应先生成独立的文件 ID 列表，再分别加载。

Python
# 简化教学代码：划分前先按患者、视频或原始图像分组。
train_ids = set(train_file_ids)
val_ids = set(val_file_ids)
assert train_ids.isdisjoint(val_ids)
assert train_ids and val_ids

若同一原图生成多个裁剪，检查裁剪文件名不重叠仍不够，还要检查原始图像 ID 不交叉。验证时应关闭训练增强，固定阈值与指标，保存失败样本便于检查粘连、漏检与边界偏移。

配置怎样影响实例分割

IMAGE_MIN_DIM、IMAGE_MAX_DIM 影响分辨率和显存，也会改变小物体在特征图上的大小。anchor scales 应与缩放后物体大小匹配，不能只看原始图像中的像素尺寸。TRAIN_ROIS_PER_IMAGE 控制每图用于训练头部的区域数量，STEPS_PER_EPOCH 则是迭代步数，不天然等于数据集完整遍历次数。

从 COCO 权重开始时，骨干与部分通用层可以复用，但类别数不同的输出头不匹配。示例加载权重时排除 mrcnn_class_logits、mrcnn_bbox_fc、mrcnn_bbox、mrcnn_mask，就是为了重新学习与新类别有关的部分。忽略形状冲突并强行加载，会让任务定义与参数不一致。

分阶段训练的 epochs 是累计终点

先训练 heads，再以更小学习率微调 all 是常见方式。但框架 train(..., epochs=...) 表示累计训练到哪一轮，而不是“本次再训练几轮”。第一阶段训练到 10，第二阶段仍写 10，可能根本没有新的轮次。应明确累计终点。

Python
# 简化教学配置示例，轮数只用于说明累计语义。
model.train(train_dataset, val_dataset,
            learning_rate=base_lr, epochs=10, layers='heads')
model.train(train_dataset, val_dataset,
            learning_rate=base_lr / 10, epochs=20, layers='all')

第二次从已完成的 10 继续到 20。恢复断点后也要检查模型记录的当前 epoch。训练日志中显示“正在训练全部层”不代表真的执行了后续迭代，必须观察迭代计数和参数更新。

如何评价自定义任务

实例分割需要按类别和 mask IoU 匹配预测与真值，再计算 precision、recall 和 AP。预测框正确但 mask 偏大，bbox AP 与 mask AP 可能分离，因此应同时关注区域指标。还要记录没有真值、没有预测、同一真值被多个预测覆盖等边界情况。

课程框架使用历史 TensorFlow/Keras API。学习时重点掌握 Dataset、候选区域、实例匹配和损失接口；迁移环境时需要整体核对依赖版本，不能只把一处 import 改名就认为完整兼容。批量转换标注的脚本只表达文件处理流程，理解后应在准备好的数据副本上明确运行范围。

类别映射不要依赖字符串模糊匹配

若用字符串包含关系寻找类别，名称相近时可能重复匹配或误配。更稳妥的做法是建立明确的标注名称到内部编号的字典，遇到未知类别立即报错。加载每个实例时同步检查类别、面积和图像范围，避免不合法标注悄悄进入训练。

抽查数据时，给每个实例画不同颜色并标出类别和序号，再把这些序号与返回数组对应。仅显示所有前景的并集无法发现两个通道交换、同类实例被合并或空通道被保留的问题。先验证接口能表达真实实例结构，再讨论学习率和训练轮数，通常能更快建立可靠实验。

练习：编号不连续

实例编号图包含 {0,2,5}，两个前景区域都属于类别 1。正确的 mask 通道数和类别数组是什么？

✅ 参考答案

有两个实例通道，类别数组为 [1,1]。最大编号 5 不代表五个实例；类别编号也不应写成 [2,5]。

练习：第二阶段为何零步

第一次 epochs=10，第二次仍 epochs=10，希望总共训练 20 轮却没有继续，怎么改？

✅ 参考答案

该接口的 epochs 是累计终点，第二次应设置为 20，并确认模型的当前 epoch 为 10。不同框架可能采用不同约定，必须根据实际训练方法的循环边界判断。
