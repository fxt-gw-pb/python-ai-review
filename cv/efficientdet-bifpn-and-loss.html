EfficientDet：BiFPN、检测头与损失

🎯 目标检测

一个检测器的三段结构

EfficientDet 由 EfficientNet 骨干、BiFPN 特征融合网络以及分类与框回归头组成。骨干给出不同分辨率的图，BiFPN 反复交换跨尺度信息，输出头对各尺度预测类别和位置。这种分工可以让我们分别分析“特征是否足够”“不同尺度是否融合好”“标签与损失是否匹配”。

D0 是理解形状的好起点。输入为 [B,3,512,512]，骨干提供 P3、P4、P5，BiFPN 进一步生成 P6、P7，并把它们统一为 64 通道，空间尺寸依次为 64、32、16、8、4。后续 BiFPN 层继续输入与输出这五张图，而不是每次重新读取原图片。

FPN、PAN 与 BiFPN 的区别

FPN 把高层语义向高分辨率传递；PAN 增加由低层向高层的路径；BiFPN 进一步简化只有一个输入的节点，增加同层跨接，并反复执行双向融合。这里的“高层”指语义深、分辨率低，“自顶向下”通常表现为上采样，不能把图中位置高低直接理解成像素分辨率大小。

每次逐元素相加前，参与融合的特征都必须有相同的通道与空间形状。通道通过 1×1 卷积调整，尺寸通过上采样或下采样调整。拼接允许通道不同，相加则不允许；这也是 YOLO 的某些 PAN 拼接模块不能直接替换成 BiFPN 加法节点的原因。

可学习的融合权重

不同输入特征的贡献不一定相同。BiFPN 为输入边分配可学习非负权重，并用快速归一化融合：

$$ O=\sum_i\frac{\operatorname{ReLU}(w_i)}{\epsilon+\sum_j\operatorname{ReLU}(w_j)}I_i. $$

这里 $I_i$ 是已对齐的特征，$w_i$ 是参数，$\epsilon$ 避免分母为零。由于存在 $\epsilon$，权重之和严格说通常略小于 1，而不是数学上精确等于 1。

下面是只演示双输入融合的可运行模块：

Python
import torch
from torch import nn

class WeightedFusion(nn.Module):
    def __init__(self):
        super().__init__()
        self.weights = nn.Parameter(torch.ones(2))

    def forward(self, a, b):
        if a.shape != b.shape:
            raise ValueError('融合输入必须先完成尺寸和通道对齐')
        w = self.weights.relu()
        w = w / (w.sum() + 1e-4)
        return w[0] * a + w[1] * b

nn.Parameter 使权重能被优化器更新；ReLU 限制权重为非负；广播把每条输入边的标量作用到整张特征图。完整 BiFPN 还会接激活与深度可分离卷积。本模块只解释权重融合，不包含完整网络的上采样和卷积。

从两输入的自顶向下节点继续向下看，会遇到三输入的自底向上节点：原同层特征、刚得到的同层中间特征、较高分辨率输出经下采样后的特征一起融合。增加的同层边让原始信息更容易保留。

共享检测头，但不同尺度的 BN 分开

分类与回归头各自重复深度可分离卷积。课内实现对不同金字塔层共享卷积参数，而为每个尺度保留独立 BN。这样既减少参数，又允许不同尺度的特征统计不同。

默认每个位置使用 3 个宽高比与 3 个尺度，共 9 个 anchor。D0 候选数为：

$$ N=9(64^2+32^2+16^2+8^2+4^2)=49104. $$

框回归输出为 [B,49104,4]，分类输出为 [B,49104,C]。这里没有 YOLO 那样单独拼在每个候选里的目标性通道，所以不能把输出当成 [B,N,C+5] 解析。回归卷积先产生 9×4=36 通道，再移动通道轴并展平；分类卷积产生 9×C 通道。

Anchor、标注和回归参数的顺序

这份实现中 anchor 存为 [y1,x1,y2,x2]，标注框却使用 [x1,y1,x2,y2]。calc_iou 专门按这两种不同顺序取值。直接把二者送入一个假定统一 xyxy 的函数，会得到错误匹配。

回归目标采用中心相对偏移与宽高对数：$d_x=(c_x^*-c_x^a)/w_a$、$d_y=(c_y^*-c_y^a)/h_a$、$d_w=\log(w^*/w_a)$、$d_h=\log(h^*/h_a)$。代码最后堆叠顺序为 (dy,dx,dh,dw)。解码必须按相同顺序还原，不能只凭“四个数”猜测含义。

Focal loss 为什么适合大量背景

候选数量很大，而真实物体很少。普通 BCE 可能被大量容易分类的背景主导。Focal loss 通过困难度权重降低容易样本的影响：

$$ L=-\alpha_t(1-p_t)^\gamma\log p_t. $$

当样本已被高概率正确分类，$p_t$ 接近 1，权重会很小；难样本仍保留较大贡献。课内代码使用 $\alpha=0.25,\gamma=2.0$。不同论文或实现可能使用不同 $\gamma$，复现时应以具体配置与代码为准。

正样本由 anchor 与真实框的最高 IoU 决定：IoU≥0.5 为正，IoU<0.4 为负，中间区域忽略。框回归只在正样本计算 Smooth L1，分类损失通常按正样本数归一化。没有正样本时也必须保持有限分母；空图片仍产生背景分类损失。

数据集与复合缩放的实际细节

COCO 格式中的类别 ID 不保证连续。课内数据读取直接做 category_id-1，只有当输出类别布局与这种减法严格匹配时才正确。自建数据建议显式建立 原始类别ID → 连续训练索引 映射，评估输出时再映射回原 ID。海洋生物样例包含一个父类别条目，也说明不能只取 categories 长度就假定它等于实际检测类别数。

批处理把标注填充为 [B,max_objects,5]，无效行类别设为 -1；损失首先剔除这些行。输入则经历 RGB 转换、归一化、等比例缩放和右下补边，框坐标同步乘缩放比例。

较大 D 系列会同时改变骨干、BiFPN 通道和层数、输出头深度与输入尺寸。课内实现对较大 compound_coef 还会关闭权重 attention 分支，因此不能宣称每个型号都执行完全相同的加权融合代码。模型选择应依据目标设备的显存、延迟和验证效果，而不是只看型号数字。

练习：定位两个接口错误

将分类输出 [2,49104,7] 当成 YOLO 输出，取前四列为坐标，会发生什么？训练标注类别为 -1 的填充行为什么必须过滤？

✅ 参考答案

这个张量的七列都是类别概率，不含坐标；把其中四列解释为框，会产生看似在0到1之间、实际毫无几何意义的结果。坐标应从独立的回归输出结合 anchor 解码。-1 是无效填充标记，若不剔除，可能错误地索引到最后一类或形成虚假的回归目标，污染损失。
