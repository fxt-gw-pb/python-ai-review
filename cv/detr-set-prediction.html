DETR：查询、注意力与集合预测

🎯 目标检测

检测可以直接学习一个集合

DETR 将检测看作集合预测。网络准备固定数量的查询槽位，每个槽位预测类别和一个边界框；训练时用一对一匹配，让不同槽位共同覆盖真实物体，多余槽位学习“无目标”。因为输出之间的重复竞争被纳入训练目标，基础推理流程不需要依赖 anchor 规则和框 NMS。

固定查询数不等于每张图固定包含那么多物体。100 个 queries 提供最多 100 个候选槽位，最终显示多少个物体由类别与置信度决定。如果数据中单图物体数经常超过查询数，模型输出容量本身就成为限制。

从 CNN 特征变成序列

输入首先通过 CNN 骨干得到 [B,C_b,H_f,W_f]，再用 1×1 卷积投影到隐藏维度 $D$。随后展平空间，变成 [H_fW_f,B,D]，交给 Transformer。这里的 token 是 CNN 特征图位置，不是直接把原始图像固定切块后送入 ViT。

Python
# 教学摘录：src 已经通过 1×1 投影，形状 [B,D,Hf,Wf]
batch_size, channels, height, width = src.shape
sequence = src.flatten(2).permute(2, 0, 1)
position = pos.flatten(2).permute(2, 0, 1)
padding_mask = mask.flatten(1)
queries = query_embedding.unsqueeze(1).repeat(1, batch_size, 1)
initial_content = queries.new_zeros(queries.shape)

flatten(2) 把高宽合并；permute 适配这份 Transformer 的序列在前布局；位置编码经过同样变形，确保位置与特征一一对应。mask 形状为 [B,H_f,W_f]，其展平结果标记补边位置，防止注意力把填充区域当成有效图像内容。

两种“位置”不要混淆

图像特征的位置编码告诉模型每个 token 在图像中的位置；object query embedding 则是每个检测槽位的可学习身份向量。初始查询内容可以全为 0，但不同 query embedding 打破了槽位对称性，让它们有机会学习不同空间和尺度偏好。

查询不等于预先指定的“这个槽位检测左上角的猫”。这种行为是训练形成的分工，查询向量在训练开始时随机初始化，之后持续学习；不是每次前向传播都重新随机生成一批 queries。

编码器与解码器分别做什么

编码器自注意力在图像位置之间交换信息。解码器有两种注意力：query 自注意力让检测槽位相互通信，cross-attention 让每个槽位从编码后的图像特征读取信息。

对一次 cross-attention，可以理解为查询内容加 query 位置形成 $Q$，图像内容加空间位置形成 $K$，图像内容形成 $V$。注意力权重计算为 $\operatorname{softmax}(QK^T/\sqrt{d_k})$，再对 $V$ 加权求和。位置帮助决定“看哪里”，内容提供“读到什么”。

经过多层解码后，输出形状为 [L,B,Q,D]。类别线性层给出 [L,B,Q,C+1]，三层 MLP 加 sigmoid 给出 [L,B,Q,4]。额外类别表示 no-object。默认配置中隐藏维度是 256，编码器与解码器各 6 层，查询数为 100。

为什么要用匈牙利匹配

真实框的顺序没有语义。交换两个标注框在列表中的位置，不应改变任务本身。因此不能强迫第一个 query 永远拟合第一个标注。

为预测 $i$ 与真实目标 $j$ 构造代价：

$$ \mathcal C_{ij}=-\lambda_c p_i(c_j) +\lambda_1\|b_i-b_j\|_1 -\lambda_g\operatorname{GIoU}(b_i,b_j). $$

匈牙利算法寻找总代价最小的一对一分配。匹配是在整个集合上共同优化，不能用“每个真实目标独立找最近预测”代替，否则多个目标可能抢到同一个预测。

Python
# 教学摘录：概率 [Q,C+1]，预测框 [Q,4]，目标框 [M,4]
from scipy.optimize import linear_sum_assignment
import torch

class_cost = -probabilities[:, target_labels]
l1_cost = torch.cdist(predicted_boxes, target_boxes, p=1)
cost = class_cost + 5 * l1_cost + 2 * negative_giou
prediction_ids, target_ids = linear_sum_assignment(cost.detach().cpu().numpy())

这里 negative_giou 是预先计算的 [Q,M] 负 GIoU 矩阵。每一项都在比较同一批预测—目标对。代价权重决定“如何配对”；后续训练损失的权重决定“配对后如何更新”，两者虽然相关，却是不同用途的参数。

匹配不求导，匹配后的损失要求导

匹配器运行在无梯度环境，得到离散索引。然后按照这些索引从原始预测张量取出配对结果，计算分类交叉熵、框 L1 和 GIoU 损失。未匹配查询只承担 no-object 分类监督，不回归虚构的空框。

eos_coef 降低 no-object 类别的分类权重，避免大量空槽位压过少量真实目标。框损失按真实物体数量归一化；分布式训练还要同步数量并防止除零。cardinality_error 记录预测物体数与真实数量的差异，在这份实现里仅用于日志，不反向传播。

辅助损失让中间解码层也预测类别与框，并对每层重新匹配、计算损失。它帮助较早层获得直接监督，推理主要使用最后一层结果。不要把辅助输出列表误当成多张图片的预测结果。

数据与输出还原

训练数据读取后先把 COCO 左上角宽高转为角点，执行翻转、缩放和裁剪，再转成归一化中心宽高。模型输出的四个值按实际代码含义为 (cx,cy,w,h)。个别注释写成 height、width 顺序时，应以转换函数与运算为准。

类别也存在协议：课内 COCO 路径保留原类别 ID，最大 ID 为 90，所以模型构造中的类别索引空间用 91，再加一个 no-object 槽；它不是简单的 80+1。自建连续类别编号的数据则可以使用真正的 $C+1$ 输出。修改自定义任务时，应同时修改数据编号、分类头和评估映射。

推理把归一化中心宽高转为角点，再乘每张图自己的 [W,H,W,H]。补边后的 batch 最大尺寸不一定等于该图的有效尺寸，使用错误尺寸会导致框整体放大。

练习：识别三个常见误区

一张图有 3 个真实物体、100 个查询，为什么未匹配的 97 个查询仍参与分类损失？为什么不能对匈牙利索引求导？为什么查询数不能解释为类别数？

✅ 参考答案

未匹配槽位必须学习 no-object，否则它们可能持续输出高置信度重复框。匈牙利匹配输出离散组合，训练通过匹配后的可微损失更新预测，而不对离散索引求导。查询数表示实例槽位容量，同一类别可占用多个槽位，一个槽位也没有固定类别身份。
