YOLOv5：结构、标签分配与训练

🎯 目标检测

版本提示：历史代码与当前 YOLO 选型

本章讲解的是较早的 YOLOv5 代码快照，采用 Focus、BottleneckCSP、Hardswish 和基于 anchor 的检测头。不要把这里的结构与当前 ultralytics 包视为同一套实现。

截至 2026-09-05，Ultralytics 官方把 YOLO26 作为新项目的优先选择，YOLO11 作为成熟方案；YOLOv8 仍用于已有工程与相关集成。YOLO26 的默认检测路径采用端到端、无需 NMS 的输出，因此旧版 YOLOv5 的 3×(C+5) 检测头与后处理代码不能直接套用。当前模型选择 · YOLO26 结构与接口

另一个容易混淆的名称是 YOLOv5u：它采用不依赖 anchor、无独立 objectness 分支的检测头。原 ultralytics/yolov5 仓库训练出的权重，不能直接用当前 ultralytics 库按 YOLOv5u 加载。学习旧版原理时保留对应工程；做新任务时，重新选择模型、依赖和匹配的预训练权重。YOLOv5 / YOLOv5u 官方说明

先认识这份 YOLOv5 的结构

本章围绕包含 Focus、BottleneckCSP、SPP 和 PAN 路径的 YOLOv5 实现展开。模型配置用 [from, number, module, args] 描述每一层：from 指输入来源，number 指重复次数，module 是模块，args 是构造参数。-1 代表上一层；列表代表读取多个分支。

这里的普通卷积模块使用 Conv、BatchNorm 与 Hardswish。模型规模通过 depth_multiple 和 width_multiple 控制，前者缩放模块重复次数，后者缩放通道数并按 8 对齐。以 depth_multiple=0.33 为例，配置中重复 9 次的模块实际变为 3 次。模型大小不是把最后检测头单独扩大，而是改变整条特征提取路径。

Focus：把空间重排到通道

Focus 分别取输入图像的偶数行偶数列、奇数行偶数列、偶数行奇数列、奇数行奇数列，再沿通道拼接。输入 [B,3,640,640] 先变成 [B,12,320,320]，之后再进行卷积。

Python
import torch

def focus_rearrange(x):
    assert x.shape[-2] % 2 == 0 and x.shape[-1] % 2 == 0
    patches = [x[..., ::2, ::2], x[..., 1::2, ::2],
               x[..., ::2, 1::2], x[..., 1::2, 1::2]]
    return torch.cat(patches, dim=1)

切片本身没有学习参数，也没有求平均，原像素被分配到新的通道中。四份切片覆盖不同位置；拼接要求它们空间形状相同，因此这个简化函数要求偶数尺寸。Focus 后的卷积才负责混合这些通道。不能把重排直接解释为“丢掉四分之三像素”。

CSP、SPP 与双向特征融合

BottleneckCSP 的一条分支经过多个残差瓶颈，另一条分支经过较短的投影路径，再把两路输出拼接、归一化和卷积融合。它让部分特征经过较深变换，部分信息保留较短传播路径。由于拼接会增加通道数，模块最后的 1×1 卷积负责重新组合并调整通道。

SPP 对同一特征分别使用 5、9、13 的最大池化核，步长都为 1，通过 padding 保持输出空间尺寸，再与原特征拼接。这份检测实现里的 SPP 主要聚合不同感受范围的上下文，不能简单理解为把任意图像池化成固定长度分类向量。

PAN 路径先上采样并融合骨干中的较高分辨率特征，再通过下采样把细节送回低分辨率路径。对 640×640 输入，三尺度输出为 80×80、40×40、20×20。假设有 2 个类别，则每个尺度的原始输出通道为 $3(2+5)=21$，解码后总候选数为 $3(80^2+40^2+20^2)=25200$。

为什么改变中心和宽高公式

这份实现把中心解码改为：

$$ c_x=(2\sigma(t_x)-0.5+g_x)s,\qquad w=(2\sigma(t_w))^2a_w. $$

中心偏移范围约为 $(-0.5,1.5)$，允许预测跨越网格边界。宽度倍率范围约为 $(0,4)$，避免指数形式在较大输入时急剧增长。对于 $t_x=t_w=0$，中心仍位于网格中点，宽度仍等于 anchor，方便理解初始化附近的行为。

Python
p = raw.sigmoid()
xy = (2 * p[..., :2] - 0.5 + grid) * stride
wh = (2 * p[..., 2:4]) ** 2 * anchor_pixels

这里 raw 是候选参数，grid 广播到每个网格位置，anchor_pixels 必须以输入像素为单位。损失内部常用网格单位 anchor，而推理使用像素单位，不能因变量名称相似就直接互换。

正样本为什么扩展到相邻网格

对每个真实框，先比较它与各 anchor 的宽高比例。若 $r_w=w/a_w$、$r_h=h/a_h$，筛选条件是 $\max(r_w,1/r_w,r_h,1/r_h)<\tau$；典型配置中 $\tau=4$。这个条件排除形状差异过大的 anchor，与解码宽高倍率范围相呼应。

随后，根据真实中心靠近网格哪一侧，给相邻网格增加监督。代码准备了中心、左、右、上、下五个偏移候选，但不会无条件把五个都作为正样本；还会依据小数位置与边界条件筛选。较常见的是中心加两个相邻位置。扩大中心解码范围，使这些相邻单元能够表达同一个真实中心。

三项损失分别学什么

框损失采用 $1-\operatorname{CIoU}$，同时考虑重叠、中心距离和长宽比：

$$ L_{box}=1-\operatorname{IoU}+\frac{\rho^2(b,b^*)}{c^2}+\alpha v. $$

其中 $\rho$ 为中心距离，$c$ 为最小包围框的对角线长度，$v$ 为长宽比差异，$\alpha$ 控制这一项的权重。分类损失使用 BCEWithLogitsLoss，接收未做 sigmoid 的 logits；若提前 sigmoid，相当于重复激活，梯度含义会错误。

目标性监督也不是简单地把所有正样本都设为 1。实现使用脱离计算图的、截断到非负的 IoU 相关值构造目标性标签，让位置质量与置信度关联。detach() 防止目标性损失通过目标标签反向改变框分支。三种尺度还有不同的目标性权重，以平衡候选数量与难度。

Mosaic 与训练循环

Mosaic 随机取四张图，拼到大画布，再做几何增强。每张图的标签先从归一化中心宽高转成像素角点，再加上粘贴偏移，最后裁剪到有效画布范围。图像拼接正确而标签没有同步偏移，会造成模型持续学习错位框。

训练循环将 uint8 图像转为浮点并除以 255，完成 warmup、多尺度调整、自动混合精度前向、损失反传和优化器更新。EMA 保存参数的指数移动平均，用于获得较平滑的评估模型；它不替代训练模型的梯度更新。

迁移训练时，应同步数据配置中的 nc 与 names、模型实际输出维度和标签类别编号。当前样例任务是两类口罩检测，而其他资料中有六类缺陷，不能复用类别表。首次复现建议先关闭复杂增强验证数据，再一次只改变一个因素，记录 AP50、AP50:95、每类 AP 与失败图。

用消融实验区分改进来源

把Mosaic、多尺度训练和模型宽度一次全部改掉，即使AP上升，也无法判断哪个因素有效。可以先固定模型与训练轮数，只比较是否开启Mosaic；再固定增强，比较输入分辨率。每组都保留相同验证集和后处理。若总体AP提升但某类下降，应结合该类实例数和错误图片解释变化，而不是仅凭平均数决定保留所有改动。

练习：从张量判断错误

两类任务的检测卷积输出是 [4,255,80,80]，最可能漏改了什么？为什么不能只修改绘图时显示的类别名称？

✅ 参考答案

255=3×(80+5)，说明检测头仍按 80 类构建。两类任务应是 21 通道。绘图名称只影响显示，无法改变模型类别 logits 数、损失标签和权重尺寸。应检查数据 nc 是否传给模型构造器、配置覆盖是否生效，以及加载旧权重时是否正确处理不匹配检测头。
