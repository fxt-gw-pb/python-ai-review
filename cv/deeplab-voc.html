DeepLabV3+：空洞卷积、ASPP 与 VOC 工程

🧩 图像分割

DeepLab：保留分辨率，扩大上下文

图像分割需要较大感受野，才能利用物体周围的环境判断类别；但不断池化会损失细边界。DeepLab 系列的重要思路，是用空洞卷积扩大采样范围，并用多尺度分支收集上下文，再结合解码器恢复细节。

空洞卷积到底扩大了什么

普通 3×3 卷积在相邻位置采样。dilation 为 $d$ 时，采样点之间间隔 $d$，等效覆盖范围为

$$k_{eff}=k+(k-1)(d-1).$$

对 3×3 卷积，dilation=1、2、3 分别覆盖 3×3、5×5、7×7 范围，但仍只有 9 个空间权重。这里的“等效覆盖”不是说每个位置都参与计算。过大的 dilation 可能跳过细节，多个空洞层还需关注稀疏采样造成的栅格问题。

“参数不增加”比较的是相同输入输出通道、相同核大小的卷积。若为了分割减少了下采样，让后续特征图变大，总计算和显存仍会增加。不能将单层参数不变推导为整个模型零成本提升。

连续三个 stride=1 的 3×3 卷积有 7×7 理论感受野，通道固定为 $C$ 且忽略偏置时参数为 $27C^2$，一个 7×7 卷积为 $49C^2$。两者覆盖范围相同，但多个非线性变换使它们不是同一个函数。

ASPP 如何组合尺度

ASPP 将高层特征同时送入 1×1 卷积、三个不同 dilation 的 3×3 卷积和图像级池化分支。池化分支得到全图上下文，再插值回同尺寸；五路各输出 256 通道，拼接为 1280 通道，最后 1×1 投影回 256。

output_stride 表示高层特征相对输入的步长。示例代码在 OS=16 时使用 rates [6,12,18]，OS=8 时使用 [12,24,36]，让更密的特征网格上保持相近的输入空间采样尺度。OS=8 的特征图面积约为 OS=16 的四倍，通常需要更多内存。

DeepLabV3+ 的低层融合

DeepLabV3+ 在 ASPP 后加入解码：高层结果上采样至低层分辨率，低层特征先压缩至 48 通道，再拼接成 304 通道。低层压缩可避免大量边缘纹理淹没高层语义。下面为 DeepLabHeadV3Plus 的原样核心节选，省略调试输出。

Python
low_level_feature = self.project(feature['low_level'])
output_feature = self.aspp(feature['out'])
output_feature = F.interpolate(
    output_feature,
    size=low_level_feature.shape[2:],
    mode='bilinear',
    align_corners=False)
return self.classifier(
    torch.cat([low_level_feature, output_feature], dim=1))

project 是 1×1 卷积、归一化和激活。aspp 汇聚不同范围上下文。插值只改变空间大小，cat 才改变通道数。解码器分类头得到低层分辨率 logits，外层模型再将 logits 恢复到输入高宽。ResNet 骨干的低层来自 layer1，高层来自 layer4；MobileNet 使用不同层与通道数，所以不要把 256/2048 通道机械套到所有骨干上。

VOC 标签读取与增强

VOC 语义分割图是调色板索引图。读取标签时保留像素类别编号，图像转 RGB，mask 不转 RGB；训练使用 21 个类别，包括背景，255 表示忽略区域。增强操作必须同时处理图像与标签，而 Normalize 只作用于图像。

随机缩放后随机裁剪是一种尺度增强；验证中心裁剪与完整图像验证得到的评估范围不同，二者不能直接混为同一实验。若不同图片高宽不一，未经 padding 或统一裁剪就拼成 batch 会失败。示例完整图验证将 batch size 设为 1，正是为了处理变长空间尺寸。

训练时交叉熵接受 [B,21,H,W] logits 与 [B,H,W] 的 long 标签。ignore_index=255 排除无监督像素；指标累计时同样过滤范围外标签。预测 max(dim=1) 返回值和索引，作为类别图使用的是索引。

训练脚本的可读结构

程序先解析配置和随机种子，再构建数据、模型、优化器与调度器。骨干参数使用分类头的 0.1 倍学习率，以较小步幅调整已有表示。Poly 学习率按迭代衰减：

$$\eta_t=\eta_0(1-t/T)^{0.9}.$$

这里 $T$ 是总迭代数，不是 epoch 数。保存断点同时保存模型参数、优化器状态、调度器状态、当前迭代与最佳 mIoU，才能完整续训。

简化教学训练步骤如下，省略了日志和可视化。

Python
model.train()
images = images.to(device, dtype=torch.float32)
labels = labels.to(device, dtype=torch.long)
optimizer.zero_grad(set_to_none=True)
logits = model(images)
assert logits.shape[0] == labels.shape[0]
assert logits.shape[-2:] == labels.shape[-2:]
loss = torch.nn.functional.cross_entropy(logits, labels, ignore_index=255)
loss.backward()
optimizer.step()
scheduler.step()

训练前先检查有效标签是否为空，否则全为忽略值的 batch 可能让平均损失无定义。ASPP 的图像池化分支空间为 1×1，训练 batch 太小时还要检查 BatchNorm 是否有足够样本统计。类数变化时，数据映射、模型头和评估矩阵需要一起改，单独传 num_classes 未必有效，因为示例主函数会按数据集名称重设类数。

把一张图的颜色结果追溯回类别索引

假设网络输出中某像素最大的通道索引为 15，这个数字首先是类别编号。显示程序再用调色板取出第十五种颜色，颜色并不参与交叉熵。如果可视化看起来颜色完全变化，而类别索引图相同，只是调色板变化；如果边界位置相同但类别名称错乱，则应优先检查训练与推理的类别映射是否一致。

需要检查失误时，可以同时保存原图、真实索引、预测索引和透明叠加图。前两张索引图适合计算指标，叠加图帮助定位错误；不要从经过压缩或颜色混合的展示图片重新还原标签。预测尺寸还应恢复到评估协议要求的原图大小，在 logits 或概率层面插值后再取类别，避免把离散类别索引当成连续数值进行平滑。

做一次可靠的骨干比较，需要保持输出步长和裁剪策略相同。把较轻骨干配较大输入，与较重骨干配较小输入比较，得到的是两个完整配置的比较，不能将差异全部归因于骨干结构。阅读实验日志时一起核对模型名、输入尺寸、实际学习率、有效标签数和验证方式，才能解释指标变化。

练习：计算 dilation

3×3 卷积的 dilation=4，覆盖多大范围？与普通 9×9 卷积的权重数是否相同？

✅ 参考答案

覆盖范围为 3+2×3=9，即 9×9，但每组输入输出通道仍只有 3×3=9 个权重；普通 9×9 有 81 个。前者稀疏采样，不能把二者视为等价运算。

练习：标签出现 255

把 VOC 标签除以 255 后交给交叉熵，为什么不正确？

✅ 参考答案

标签是类别索引，不是图像亮度。除以 255 会破坏 0 到 20 的类别编号，也把忽略值变成 1。应保持整数标签，使用 ignore_index=255，并让指标过滤同样的无效区域。
