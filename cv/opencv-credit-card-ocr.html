模板 OCR 实战：从信用卡数字组到逐字识别

🖼️ OpenCV 图像处理

把问题拆成定位与识别

本案例识别特定样式的卡面数字。它先从参考图得到 0–9 模板，再定位输入图中的数字组，切开组内字符，最后选择相似度最高的数字。这里没有训练字符网络，模板字体、前景颜色、尺寸和布局约束承担了大部分先验。因此它适合学习完整流水线，不能被理解为支持所有字体和任意卡面的通用 OCR。

建立十个数字模板

参考图经灰度和反二值阈值处理，变成白色数字、黑色背景。只取外轮廓，按外接矩形的 x 坐标从左到右排序。原码依赖参考图本来就是 0、1、2、…、9 的顺序，将排序后的第 $i$ 个字符直接记作数字 $i$。

每个轮廓裁出紧致 ROI，再缩放为宽 57、高 88。统一尺寸使后续相似度具有相同空间范围，但这种非等比拉伸也会改变笔画比例，因此参考模板和输入字符必须采用相同处理。

Python
import cv2

ref = cv2.threshold(reference_gray, 10, 255, cv2.THRESH_BINARY_INV)[1]
contours = cv2.findContours(ref.copy(), cv2.RETR_EXTERNAL,
                            cv2.CHAIN_APPROX_SIMPLE)[-2]
contours = sorted(contours, key=lambda c: cv2.boundingRect(c)[0])
if len(contours) != 10:
    raise ValueError('参考图应分出 10 个数字')
digits = {}
for digit, contour in enumerate(contours):
    x, y, w, h = cv2.boundingRect(contour)
    digits[digit] = cv2.resize(ref[y:y+h, x:x+w], (57, 88))

这段是原流程的教学简化，增加模板数量检查，并使用兼容轮廓返回格式的末尾索引。boundingRect 返回 (x,y,w,h)，原工具函数注释中写成 x、y、h、w 是次序错误，学习时应以实际解包和裁剪为准。

用形态学把数字组凸显出来

输入图等比例缩到宽 300，这不是任意选择：后面的大量宽高阈值都是在这个尺寸下制定的。先将灰度图做宽 9、高 3 的礼帽操作，突出比局部背景亮的小结构；再计算 x 方向导数，增强数字竖向笔画的左右边界。

原码在 Sobel 中使用 ksize=-1，这是特殊的 Scharr 路径，不应把它简单解释成普通 3×3 Sobel。随后取绝对值，做最小最大归一化到 0–255。若输入基本平坦导致最大值等于最小值，分母为 0；改写时必须处理。

Python
import numpy as np

rect_kernel = cv2.getStructuringElement(cv2.MORPH_RECT, (9, 3))
tophat = cv2.morphologyEx(gray, cv2.MORPH_TOPHAT, rect_kernel)
gradient = np.abs(cv2.Sobel(tophat, cv2.CV_32F, 1, 0, ksize=-1))
span = float(gradient.max() - gradient.min())
if span > 0:
    gradient = ((gradient - gradient.min()) * (255.0 / span)).astype('uint8')
else:
    gradient = np.zeros_like(gray)
joined = cv2.morphologyEx(gradient, cv2.MORPH_CLOSE, rect_kernel)
binary = cv2.threshold(joined, 0, 255, cv2.THRESH_BINARY | cv2.THRESH_OTSU)[1]

闭运算把组内数字连接起来，再用 Otsu 阈值提取数字组候选。原流程还加一个 5×5 闭运算补缝。这一步找的是“四个数字组成的条块”，不是单个数字，所以核应跨过组内间隙，但尽量不跨过组间大间隔。

几何筛选为何和分辨率绑定

原码保留宽高比 2.5–4.0、宽 40–55、高 10–20 的轮廓，然后从左到右排序。这些数值说明它针对示例卡面、缩放尺寸和四位分组设计。换图片后识别不到数字，首先检查是否在定位阶段就把候选全删掉，而不是马上怀疑模板匹配。

每个组向外扩展 5 像素，在原灰度图上重新裁剪和二值化，再找单字轮廓。扩边会触及图像边缘，应把起点截到 0、终点截到图像宽高；负切片索引表示从末尾计数，并不表示自动补黑边。

单字符如何变成分类结果

下面概括原来的逐字符循环，roi 已缩放为 (57,88)，digits 是模板字典：

Python
scores = []
labels = []
for digit, template in digits.items():
    response = cv2.matchTemplate(roi, template, cv2.TM_CCOEFF)
    score = cv2.minMaxLoc(response)[1]
    labels.append(digit)
    scores.append(score)
predicted = labels[int(np.argmax(scores))]

两张图大小相同，得分图为 (1,1)，此时滑动定位退化为同尺寸图案比较。TM_CCOEFF 去掉局部均值后计算相关量，越大越相似。显式保存 labels，可以避免“列表下标恰好等于数字标签”的隐含假设。进一步还可以检查最佳与次佳分数差距，给难以区分的字符返回待检查，而非强行输出。

原程序用识别首位查询卡类型映射。这是案例中的示例字典，不能把它当作完整的卡号规则。若没有找到任何数字，直接访问 output[0] 会报错；若首位不在字典中，直接索引也会报错。教学实现应先检查识别是否为空，再允许未知类别。

调试应按哪种顺序看图

依次保存参考模板、礼帽图、梯度图、组掩模、候选框、单字 ROI 和十个得分。若字符 ROI 本身包含两个数字，换模板评分方法也难以补救；若模板分割顺序错误，所有相似度都算对仍会输出错误标签。把定位错误与分类错误分开统计，才能知道该调核、阈值还是模板。

练习

  1. 为什么输入先缩到宽 300，再筛选宽度 40–55？
  2. 字符和模板大小一样时，为什么仍可调用 matchTemplate？
  3. 若参考模板图不是按 0–9 排列，需要改什么？
✅ 参考答案
  1. 几何阈值在统一尺度下才有意义；原图分辨率不同而不缩放，会使同样的数字组落在不同像素宽度。
  2. 只有一个合法滑动位置，输出一格分数，正好用于比较对齐后的图案。
  3. 需要显式标注每个模板的真实标签，不能把排序序号直接当作标签；分类返回标签表中的元素，而不是简单返回得分数组下标。
