几何视觉的两种应用：全景拼接与答题卡判卷

🖼️ OpenCV 图像处理

两个项目共用的几何思路

全景拼接要把两张照片映射到共同坐标系，答题卡判卷要把斜拍页面映射到规则坐标系。二者都依赖“先建立几何对应，再解释像素”的顺序。拼接从图像特征估计对应，答题卡从纸张四角获得对应；对应关系错了，后续贴图和答案统计都会错。

全景拼接：先读清图像顺序

原 Stitcher 接收两张图片，却在内部赋值为 (imageB, imageA)。随后对 A 求变换，投到 B 的坐标系，最后把 B 覆盖在结果左侧。阅读时必须沿变量流向确认哪张是查询图、哪张是目标图，不能只根据调用者变量名里的 A、B 猜测。

流程是 SIFT 检测与描述、KNN 匹配、0.75 比值筛选、RANSAC 单应性估计、透视变换和覆盖。detectAndDescribe 中虽然计算了灰度图，实际传给特征函数的却是 image；教学改写宜明确使用灰度变量，使代码与处理意图一致。

Python
import cv2
import numpy as np

pairs = cv2.BFMatcher().knnMatch(desc_a, desc_b, k=2)
good = [p[0] for p in pairs
        if len(p) == 2 and p[0].distance < 0.75 * p[1].distance]
if len(good) < 4:
    raise ValueError('有效匹配不足')
points_a = np.float32([keypoints_a[m.queryIdx].pt for m in good])
points_b = np.float32([keypoints_b[m.trainIdx].pt for m in good])
H, inliers = cv2.findHomography(points_a, points_b, cv2.RANSAC, 4.0)
if H is None or inliers is None or int(inliers.sum()) < 4:
    raise ValueError('不能建立可靠的几何变换')

这段是原匹配函数的教学改写。queryIdx 对应 A，trainIdx 对应 B，所得 $H$ 将 A 投到 B。4.0 是重投影误差的像素阈值，分辨率改变后容差意义也变化。四对非退化点是理论最低条件；原函数用了大于四对的判断，属于更保守的实现选择。

拼接画布为什么会裁掉内容

原程序给结果分配“宽等于两图宽度之和、高等于 A 高度”的画布，再把 B 贴到左侧。它适合示例中较简单的左右关系，但透视变换后的 A 可能超出上下边界，或者出现负坐标。更通用的做法是变换 A 的四个角，与 B 的四角合并求整体范围，再增加平移矩阵，把最小坐标移到非负区域。

直接覆盖也不是融合。重叠部分的曝光、颜色或物体位置不同，会出现明显接缝与重影。可以先比较曝光与配准误差，再考虑重叠区加权或多尺度融合；几何错位不能只靠模糊接缝消除。场景视差大、人物移动、两图缺少重叠时，应该报告不能可靠拼接，而非强行贴出一张图。

答题卡：校正后再统计选项

判卷先灰度、平滑与边缘检测，寻找纸张外轮廓，近似成四边形并透视拉正。随后使用 THRESH_BINARY_INV | THRESH_OTSU，把黑色笔迹变为白色前景。之所以反二值，是因为后续要统计非零像素数，涂得越实的区域应有越多白像素。

候选选项用外接矩形筛选：宽、高至少 20 像素，宽高比约为 0.9–1.1。这只近似约束“大小合适且接近正方形”，不是严格圆形判定。页面分辨率、选项大小和拍摄姿态改变后，阈值需要重新解释。

先按 y 坐标从上到下排序，每五个划为一道题，再在每题内部按 x 从左到右排序。这个算法假设五个选项排成一行，且没有漏检或多检。只要少找到一个圆圈，后续每五个分组都会错位；因此分组前应检查总数，并验证一组中 y 坐标是否接近、相邻行是否分离。

掩模内非零计数如何判定答案

Python
counts = []
for contour in option_contours:
    mask = np.zeros(binary.shape, dtype='uint8')
    cv2.drawContours(mask, [contour], -1, 255, -1)
    inside = cv2.bitwise_and(binary, binary, mask=mask)
    counts.append(cv2.countNonZero(inside))
chosen = int(np.argmax(counts))

这段保留原判卷核心。填充掩模限定某个选项内部，只统计该区域中原二值图的白像素；它不是对灰度亮度求和。外轮廓包含内部填涂，即使边圈是空心的也能用实心掩模覆盖整个选项区域。

原算法无条件取最大值，所以空白题也会被强行选一个，双选题也只会留下一个。可扩展为填涂比例 $r_i=\text{非零像素数}/\text{掩模面积}$，同时判断最大比例是否足够高、前两名是否过于接近。阈值应由空白、正常填涂和涂改样本估计，而不能随意宣布某个常数适用于所有答题卡。

得分、标签与显示也有假设

原答案字典的题号和选项号都从 0 开始，每题五个选项，对五道题计算 correct / 5.0 * 100。教学改写可改成依据答案字典长度计算，并先检查检测题数是否匹配；否则多一行或少一行会造成索引错误或错误分母。

另一个细节是原程序在灰度 warped 上用 BGR 三元组表示红绿颜色。要稳定显示彩色批注，应先将灰度转换成 BGR，再绘制。数值统计继续用未被画线污染的二值图，展示使用独立副本。

练习

  1. 交换 findHomography 的两组点，结果还是同一个变换吗？
  2. 为什么只有很高的模板匹配分数，仍不足以支撑拼接？
  3. 一张答题卡全部未填，原算法会得到“未作答”吗？
  4. 选项圈大小略有差异时，直接数白像素可能有什么偏差？
✅ 参考答案
  1. 方向改变了，新变换近似对应原变换的逆，不能继续按原方向调用 warpPerspective。
  2. 还需足够且分布合理的几何内点；重复纹理、退化位置和视差都会让外观相似失去可靠几何意义。
  3. 不会，它总取每组最大值。应加入最低填涂要求与多选、空白状态。
  4. 大圈的可统计区域更大，空心边框也可能带来更多白像素。使用面积归一化、模板化选项区域及合理阈值更便于比较。
