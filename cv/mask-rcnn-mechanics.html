Mask R-CNN：FPN、RPN、ROIAlign 与 mask 损失

🧩 图像分割

Mask R-CNN：检测与实例掩码的共同流程

Mask R-CNN 先寻找值得关注的候选区域，再对每个区域预测类别、精确边框和二值 mask。它保留每个物体的身份，因此能区分站在一起的两个人。读代码时可以按“骨干与 FPN → RPN → 候选区域筛选 → ROI 对齐 → 三个任务头”追踪。

FPN：给不同大小物体准备不同尺度

骨干网络输出多阶段特征 C2 到 C5，浅层分辨率高，深层语义强。FPN 从 C5 开始用 1×1 卷积统一通道，再自顶向下上采样，与对应浅层投影相加。每个融合结果再用 3×3 卷积整理，形成 P2 到 P5；额外 P6 用于 RPN 的大尺度 anchor。

注意 FPN 的融合是加法，要求两路通道相同；U-Net 的跳跃通常是拼接。两者都利用高低层信息，但张量计算不同。示例 FPN 各层为 256 通道。小物体在更细网格上仍占有可辨认的区域，因此多尺度特征特别有价值。

RPN：每个 anchor 的两类分数和四个偏移

每个特征位置预设若干长宽比与尺度的 anchor。若一层大小 $H_l\times W_l$，每个位置有 $A$ 个 anchor，该层共有 $H_lW_lA$ 个候选。全部 FPN 层相加，数量可非常大。

RPN 先共享一个 3×3 卷积，再分成两条 1×1 输出分支：分类分支输出每个 anchor 的背景/前景 logits，形状 [B,N,2]；回归分支输出 [B,N,4]。所谓“三个输出”指 logits、概率、偏移三组张量，不是每个框只有三个数。

边框变换通常用中心偏移和尺度比：

$$t_y=(y^*-y)/h,\quad t_x=(x^*-x)/w,\quad t_h=\log(h^*/h),\quad t_w=\log(w^*/w).$$

解码时恢复中心，再用指数恢复宽高。像素坐标与归一化坐标不要混用，代码常用 (y1,x1,y2,x2)，与一些库的 (x1,y1,x2,y2) 顺序不同。

ProposalLayer 怎样减少候选数量

先按前景概率选择得分靠前的 anchor，再应用回归偏移、裁剪到图像边界，然后通过 NMS 抑制高重叠框，最后按需要补零到固定数量。NMS 处理的是多个候选的冗余，不是直接得到分割 mask。

示例逻辑可以概括为以下简化教学代码。

Python
scores = rpn_probs[..., 1]
indices = topk(scores, k=min(6000, number_of_anchors))
boxes = apply_deltas(anchors[indices], deltas[indices])
boxes = clip_to_image(boxes, image_shape)
keep = nms(boxes, scores[indices], threshold=nms_threshold)
proposals = pad_to_count(boxes[keep], proposal_count)

topk 降低后续计算量；apply_deltas 把粗 anchor 修正为候选框；clip 约束坐标范围；nms 按阈值去冗余。这里的函数名用于展示数据流，不能当作已导入的可直接运行 API。

ROIAlign 为何对 mask 更重要

ROIPooling 中坐标量化可能带来位置偏差。分类对少量位移通常较宽容，mask 边界却依赖精确对齐。ROIAlign 保留浮点坐标，用双线性插值得到采样点特征，然后生成固定大小区域表示。

FPN 还会按 ROI 面积选择合适层级。较小 ROI 选较高分辨率层，较大 ROI 选更粗层。读取实现时要看它具体怎样采样：示例用 tf.image.crop_and_resize 实现每格简化采样，不能把所有 ROIAlign 实现都说成完全相同的“四点平均”。

训练目标只分配给有意义的区域

候选框先去掉补零，再与真实框计算 IoU。IoU 足够高的候选作为正 ROI，低于阈值的候选作为负 ROI；每个正 ROI 匹配到最合适的真实实例，继承类别、边框回归目标与裁剪后的 mask。COCO crowd 区域在此有特殊处理，不能简单当成普通实例。

基础配置是每图 200 个训练 ROI，目标正例比例 0.33，约为 1:2 的正负比；自定义配置可覆盖这些数值。正例不足时实际数量会变化，补零也不等于产生真实负例。把固定数量与采样上限分清，才能理解损失中为什么再次过滤有效区域。

五类损失如何合作

整体损失由 RPN 分类、RPN 边框、最终分类、最终边框和 mask 五项组成。分类帮助区分类别，回归改善框，mask 学习区域轮廓。mask 头对每个 ROI 输出多个类别通道，但训练只取正 ROI 对应真实类别的那一个通道做二元损失。

简化教学代码如下，假定预测 mask 已经是概率。

Python
positive = target_class_ids > 0
roi_ids = torch.where(positive)[0]
class_ids = target_class_ids[positive]
chosen = predicted_masks[roi_ids, class_ids]
truth = target_masks[positive]
if roi_ids.numel() == 0:
    mask_loss = predicted_masks.sum() * 0
else:
    mask_loss = torch.nn.functional.binary_cross_entropy(chosen, truth)

这解释了为何负 ROI 不需要真实 mask：它们只参与背景分类。实例 mask 不使用跨类别 softmax 争夺像素，而是每个实例在自身 ROI 内判断前景。推理时再把小 mask 放回预测框，并还原到原始图像坐标。

一张图中两个相邻实例如何流转

两个人站得很近时，RPN 可能产生覆盖单人或同时覆盖两人的多个候选。目标分配不是简单给候选套上所有相交类别，而是根据与真实框的重叠为正 ROI 选择对应实例。头部随后在该 ROI 内学习那个实例的 mask；即使区域中出现另一个人，其像素也不应被当前实例 mask 一并覆盖。

这也是为什么只保留语义前景图会削弱实例监督：两个人的区域被并在一起后，训练目标不再说明哪一部分属于哪一个人。推理的多个实例 mask 允许一定重叠，但评价会按实例一对一匹配，重复预测同一个人仍会产生假阳性，不能用所有 mask 的并集掩盖重复检测。

排查漏检时应沿流程定位。若正确位置根本没有候选，优先看骨干尺度、anchor 和 RPN；若候选存在但类别错，查看 ROI 特征与分类；若框正确但轮廓错，检查 mask 分辨率、目标裁剪和坐标还原。分阶段检查比只看最终叠加图更能找到改动方向。

练习：anchor 数量

某层特征为 64×64，每位置 3 个 anchor，这层有多少候选？RPN 的类别与回归输出各是什么形状？

✅ 参考答案

候选数为 64×64×3=12288。展平后分类 logits 为 [B,12288,2]，回归为 [B,12288,4]。多层 FPN 会沿候选轴继续拼接。

练习：只训练真值类别 mask

正 ROI 的真实类别是“人”，mask 头还输出了“猫”的通道。该 ROI 的猫通道也要和人体 mask 比较吗？

✅ 参考答案

不用。选择人体对应通道计算二元 mask 损失，类别由独立分类头监督。强迫其他类别通道拟合同一人体 mask，会破坏类专属分支的含义。
